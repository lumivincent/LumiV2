# RC-005 · Canopy Finance 独立营销研究

> 研究快照：2026-09-03 · 证据状态：收购与收入用途由官方账号披露；财务数字未独立审计。

## 1. 项目身份与母帖

Canopy 将自己定位为 `Programmable Markets & Intelligence`，并在官方帖中宣布购买 v4.fun、继续建设 Robinhood Chain 的 Uniswap v4 Hook launchpad，[收购帖](https://x.com/canopyfinance/status/2091966279787663847)。[P1](https://x.com/RobinHubHB/status/2095198531393040724) 以“Canopy 的 v4.fun”称呼二者，证明外部媒体已把品牌关系压成一个生态叙事。

## 2. 背景与入场

Canopy 以 DeFi 产品和 v4.fun 联动进入 Robinhood Chain 讨论，合作方本身也是分发节点。

## 3. 高表现推文拆解

收购帖的结构是：明确动作 `We purchased v4.fun` → 域名本身带来的记忆点 → “best v4 hook launchpad”愿景 → 把复杂 Hook 降低为任何人可创建/理解/发布的 programmable markets。它让收购既是公司新闻，也是新品类教育，[原帖](https://x.com/canopyfinance/status/2091966279787663847)。

[恢复 buybacks/burns 帖](https://x.com/canopyfinance/status/2095276610706448497) 把 v4.fun 收入用于 CNPY 回购的比例从 80% 提到 100%，并附已执行金额。该内容把子产品使用量与母品牌代币连接，但数据属于项目自报，不能直接视为价值保证。

## 4. 活动、拉新与裂变

其主要转化来自产品联动和新资产/市场入口，未发现可验证的推荐码裂变。

## 5. KOL 与分发路径

Canopy 与 v4.fun 相互点名 → 各自用户交叉触达 → RobinHub 日报放大。

## 6. 热度形成判断

Canopy 使用“双账号协同”：母账号解释收购、收入与生态，v4.fun 账号发布产品和 builder 叙事。两边互相引用，使同一事件获得两套受众；RobinHub 再以成交量里程碑进入日报，[P1](https://x.com/RobinHubHB/status/2095198531393040724)。没有证据证明 RobinHub 收录为付费。

## 7. 对 Lumiterra V2 的启示

当母品牌与子产品职责确实不同，可以分别经营“公司/经济解释”和“产品/创作者体验”，但必须让用户看得懂关系。Lumiterra 若未来有 Agent 工具、游戏入口或资产模块，可采用双层内容结构；当前不应为营销而提前拆多个空账号。

## 8. 未验证事项

收购对价、团队整合、v4.fun 收入核算、回购交易、CNPY 持有人转化和媒体/KOL 商业关系未公开。
