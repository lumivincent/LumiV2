# Lumiterra V2 · 当前运营状态

## 当前阶段

V2 仍处于 Early Prototype。现阶段的运营主线是持续理解产品变化，建立稳定叙事，并为后续内容、活动与物料准备可复用上下文。

## 当前工作重点

- 对齐需求文档与数值文档的最新变化
- 区分已确认事实、运营判断与待确认假设
- 沉淀 Agent、Fully Onchain、成长与经济循环的对外表达
- 让每次分析和创作都成为下一次工作的上下文
- 已建立独立运营知识库入口与空白数据空间，用于零散外部信息的收集、证据追溯、讨论与观点沉淀；知识库范围不局限于 Olympus DAO

## 视觉创作工作方式

- 视觉创作分为创作、素材库、我的作品三个独立视图
- 创作有生成新图、修改图片、内容配图、连续创作四个平级入口；素材不要求关联推文或其他内容
- 四种创作类型使用同一条表单流程和底部唯一“生成图片”按钮；创意完善与单独保存方案不再占据主操作区
- 表单顺序固定为创作类型、类型专属输入、作品信息、画面目标、参考资料、更多设置和生成；执行方式、比例、精细度与补充要求默认收起
- 图片参考与知识库参考合并为紧凑的“参考资料”区域，只展示数量、已选缩略图和添加入口
- 四种创作类型的“画面目标”均支持直接输入 `@图片编号`；候选只显示本次已选参考图，未选图片必须先通过“添加图片”加入
- 修改图片必须先选择唯一修改对象；普通参考图片保持独立多选，不与修改对象混用
- 每张图片拥有稳定的 `IMG-*` 或 `REF-*` 编号；输入框使用 `@编号` 可精确引用已上传或已生成图片
- 作品名称可修改，但稳定编号和版本链不变；新作品使用独立随机分组，避免同名作品被错误合并
- 内容与素材只在需要时建立关联；从内容带入创作时可以选择不保存关联
- 连续创作保存创作名称、固定视觉规则、参考作品和 Codex 会话；首张建立完整记录，后续版本走轻量继续生成
- 内容草稿和图片制作中的未完成输入保存在本机，刷新后自动恢复
- 参考素材可以设为默认参考，新建创作时自动带入；最近使用的连续创作可一键恢复
- 文字任务与图片任务使用独立执行通道，可以同时处理
- 本地上传的角色、场景、Gameplay、Logo、风格和 UI 图片归入参考素材
- 参考素材支持一次批量上传最多 20 个文件；素材库使用紧凑缩略图网格，保持快速浏览和选择
- 图片制作可从素材库多选任意数量的参考图片，前端与生成接口不再只保留前 4 张
- 图片生成中的等待状态直接显示在结果区；API 失败会保留错误说明、错误码和请求编号，刷新后仍可查看
- 本地 OpenAI 图片与内容请求通过 Clash 本机代理连接；Windows 默认使用 `127.0.0.1:7897`，可用 `OPENAI_PROXY_URL` 覆盖
- 图片制作可在 Codex ImageGen 与 OpenAI API 之间直接切换；两种方式共用参考素材、系列规则、内容关联和作品版本链
- 在两种图片执行方式之间切换时保留 Codex 会话线索，方便继续沿用已有视觉上下文
- 每组生成作品保存创作会话、最近八轮调整与前序要求摘要；当前结果下方可以继续对话修改
- API 图片首轮保持直接生成，后续修改进入 Responses 图像会话；切换执行方式时用当前图片和已确认要求承接，不复用另一执行方式的隐藏上下文
- 生成作品按同一创作主题保留版本，创作要求与执行记录随作品查看
- 当前结果区直接显示同一创作的全部版本缩略图；点击任一版本即可查看并从该版本继续修改
- 切换工作台顶部 TAB 或刷新页面时保留当前素材创作、所在子页面、结果、版本、参考、本轮调整和继续迭代状态；只有新建或载入另一项创作时才确认切换
- 图片文件生成后立即显示并登记，创作说明与执行记录可以继续在后台完成
- 视觉创作始终显示“新建图片”和“取消本次创作”；取消会清空本次编辑状态并返回“我的作品”，不删除作品与版本
- 当前图片结果只保留一个继续迭代入口：有调整要求时为“继续修改”，无调整要求时为“再生成一版”；不再重复显示载入与再生成按钮
- 生成结果可直接“采用此版本”；采用后进入完成态，只保留开始新图片、基于此图继续迭代、下载与参考标记等后续动作

## Marketing 工作方式

- Marketing 是独立一级入口，用于轻量整理运营 Timeline 与 Todo，不替代内容创作或视觉创作
- Timeline 和 Todo 可以分别新建、编辑、复制、更新状态和删除；Todo 可选归入某个 Timeline，也可保持独立
- 现有推文与素材不会自动进入 Marketing，只有用户在记录中主动选择时才建立关联
- 删除 Marketing 记录只删除计划或任务本身，不删除关联的推文、图片或素材文件；删除 Timeline 后，其 Todo 保留并转为未规划
- Timeline 按日期快速浏览，Todo 优先显示未完成事项；第一版保持轻量列表，不引入复杂日历和自动流程

## 线上部署方式

- Railway 使用 Next.js standalone 单服务部署，运行时监听平台提供的 `PORT` 和 `0.0.0.0`
- 线上工作区统一使用 `WORKSPACE_ROOT=/data/workspace`，Railway Volume 挂载在 `/data`
- 空 Volume 首次启动时从部署包初始化项目记忆、产品资料、知识库、记录和 metadata；后续启动只补充缺失文件，不覆盖线上数据
- Railway 线上数据以 Volume 为准，不自动回写 GitHub；GitHub 保存代码和首次初始化内容，Volume 需要独立备份
- 线上访问通过 `APP_ACCESS_USERNAME` 与 `APP_ACCESS_PASSWORD` 提供基础保护；未设置密码时不启用保护
- Railway 不使用本机代理变量，OpenAI 请求直接使用服务端 `OPENAI_API_KEY`

## 内容工作方式

- 内容工作台只负责基于当前 Marketing 需求快速创作，不承载规划和排期
- 最新 `sources/` 决定现在能够确认和对外表达的产品事实
- 只有定稿和已发布内容进入长期表达记忆，草稿不作为后续创作依据
- 每条定稿记录当时的产品文档版本；产品更新后，相关历史内容进入待复核状态
- 热点、链接和临时市场背景只作为本次创作上下文，不自动沉淀为长期事实
- 内容创作可在 Codex 与 OpenAI API 之间直接切换；两种方式共用产品事实、定稿表达和同一内容记录
- OpenAI API 内容创作默认使用 `gpt-5.6-sol`；页面显示的模型、保存记录与实际接口配置保持一致
- 内容创作默认先生成三个核心观点与 Hook 明显不同的方向；只有用户选中后才写入正文版本并进入单线精修
- 已选方向随内容保存；后续快捷修改默认只调整指定部分，不擅自改变核心观点、事实和叙事方向
- OpenAI API 每次只读取与当前任务相关的产品片段、最多四条相关定稿内容、当前草稿和本次背景，不全量发送历史记录
- API 的模型与 Token 用量随内容记录保存，方便查看成本；草稿仍不进入长期表达记忆
- 每条内容保存创作会话、最近八轮修改和前序要求摘要；Codex 使用线程续接，OpenAI API 使用 Response ID 续接
- 会话达到八轮或切换执行方式时自动整理前序调整，再从当前版本继续，避免上下文无限增长
- 内容创作可以按任务显式选择知识库主题、结论或资料；引用会随内容记录保存，但知识库不能覆盖最新产品文档
- 内容创作的知识库选择器使用居中双栏弹窗，先看摘要与全文预览再确认引用；窄屏自动收敛为单栏选择
- 同一条内容最多保留最近 30 个正文版本；每次生成或正文变化都会新增版本，可查看旧版、从旧版继续修改或恢复为当前版本
- 从历史版本继续时会开启新的 API/Codex 上下文分支，避免旧正文错误续接到最新版本的隐藏会话
- 方向选择是独立界面状态，不与旧预览、版本历史和编辑工具同时出现；选定后收起为当前方向并进入单线精修
- 内容版本默认收起为“当前版本 / 查看全部版本”入口，需要时再展开历史，避免横向版本条长期占据正文空间
- 快捷操作只直接保留强化开头和压缩；语气调整、翻译、Thread 与配图分别收进两个操作菜单
- 定稿必须先执行事实与公开风险检查，再由用户确认；定稿后正文只读并进入完成态，发布、基于此稿继续和开始下一条成为明确后续动作
- 内容创作始终提供新建与取消：取消方向选择不改原文，取消编辑恢复最近保存版本，新建不会删除历史草稿或定稿

## 分析工作方式

- 新建分析使用居中的多轮对话工作区，可在 Codex 与 OpenAI API 之间切换、继续追问或随时停止
- 文档源固定分为需求文档、数值文档、Agent 交互和抽奖交互四类；每次更新必须先完整拉取四类内容，再统一写入，不能只更新部分分类
- 需求与数值保存原始 Markdown，Agent 与抽奖保存原始交互 JavaScript 和官方样式；原文件按哈希留存版本，交互稿通过本地轻量播放器快速查看，并保留官方原稿入口
- Agent 与抽奖分别提供面向人的“快速理解”和面向模型的结构化证据包；分析优先读取页面结构、操作路径、状态、文案和关键逻辑，不直接把整份渲染代码作为主要上下文
- 分析可以从某一分类直接发起，只读取该分类最新完整源文件；全局新建分析才默认读取全部四类文档
- 分析结果记录本次使用的文档分类，并可按任务显式选择知识库资料；满意后才保存为分析结果，对话过程不占用分析结果列表
- 分析与知识讨论共用交互样式和会话记录，但仍是独立工作类型
- 对话弹窗使用单一内部滚动区；空白会话将说明与输入框集中在视线中心，主操作始终清晰可见

## 运营知识库边界

- 知识库是独立一级入口，不占用、搬移或改造现有文档分析、内容创作和素材工作区
- 知识库使用独立的 `knowledge/` 目录和 `data/knowledge-*` metadata；初始保持空白，不导入现有内容
- 知识库前台优先提供三步阅读路径：主题用于快速建立全貌，结论用于掌握每次讨论后的最新判断，资料用于获得高密度信息和直接核对源头；ID、版本、状态等追溯字段默认隐藏在后台
- 知识库采用双栏阅读：左侧保留主题、结论和资料入口，点击后右侧原位展开全文，不跳转整页、不需要返回
- 知识库顶部使用单行紧凑工具栏，标题说明、搜索和记录入口并排展示，把首屏空间优先留给知识正文
- “记一条”使用居中对话弹窗：支持 Codex / OpenAI API 多轮讨论、单条结论或整段总结一键加入知识库，也支持跳过 AI 直接添加资料、结论、主题或讨论文档
- 知识讨论会话独立保存；关闭后可继续上次会话，只有用户明确点击加入时才写入知识库
- 直接添加资料提供独立原始链接字段，主题关联只展示主题；未保存输入在当前浏览器会话中自动恢复
- 文档分析、内容创作和素材制作都可以通过同一选择器引用知识库，并记录引用版本与目标产出
- 外部案例、行业资料和运营观点进入独立知识库，不写入 `sources/` 产品事实
- Olympus DAO 是首个研究与流程试点，不是知识库的永久范围
- 日常资料搜集、分析和脑暴讨论默认不生成前台过程卡片；新资料加入对应资料页，新判断直接更新对应结论页，并同步修订主题页
- 结论页顶部保留每次讨论带来的新增、修正或推翻，方便快速掌握变化；研究过程只保留在会话记录，不占用知识库阅读入口
- 未整理资料与未复核观点不自动进入公开内容的创作上下文
- 研究结论必须能够追溯到具体来源、证据片段和历史版本
- 主题不设为全工作台状态；分析、内容和素材按本次任务显式选择知识库参考，避免无关主题被自动带入
- 各模块默认读取知识库，只有用户在完成态主动确认才会写回；分析结果、定稿内容和已采用素材可新增结论、更新现有知识或仅关联主题
- 知识库首页提供“新建主题”；沉淀弹窗可选择现有主题或现场新建，未选主题的内容允许保存为待归类
- 更新现有知识保留稳定 ID、旧版快照和递增版本；保存前提示相近条目，优先减少重复结论
- 产出正文和媒体文件仍保留在原工作区，知识主题页只展示相关工作的关联入口，不复制完整产出

## 对外表达边界

- 不提前承诺未经确认的上线日期
- 不将仍在调整的数值作为确定卖点
- 不做 Token 收益或结果保证
