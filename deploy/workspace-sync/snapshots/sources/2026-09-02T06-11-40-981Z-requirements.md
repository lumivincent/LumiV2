# Lumiterra V2 产品需求文档

> 本文档只记录产品与业务需求。数值、公式和成长曲线统一参考 [`numeric-core.md`](./numeric-core.md)。

## 1. 产品概述

Lumiterra V2 是运行在 Monad 上、由 Agent 主导、以 OHM 为底层经济资产的 Fully Onchain 养成放置类游戏。整体经济结构参考早期 OHM 的 Bond、协议利润与 Stake 机制，但用 Agent 作为 Stake 载体，并把被动 rebase 改造成需要实际游戏产出才能兑现的 OHM 额度。

玩家使用 MON 按 `1:1` 充值为不可交易的 `Energy`。Energy 只有两条互斥用途：用于 Agent 运行、游戏行为和成长消耗，或用于抽奖式 Bond。只有抽奖式 Bond 产生 OHM 和协议利润；游戏成长消耗的 Energy 不进入 OHM mint 额度。玩家把已解锁 OHM 注入 Agent 后获得质押权重，Agent 再通过战斗、采集和种田产出素材，把按质押权重分得的 OHM 额度逐步兑现并自动复投。

## 2. 角色与控制

游戏只有一种角色模型。Agent 和人类宠物是两种控制入口，不是两套角色或成长系统。所有账户默认没有 Agent，玩家可以先选择宠物形象免费进入游戏，Agent 需要后续购买。每个人类账户最多只能购买、绑定和持有一个 Agent；一人一 Agent 是协议级约束，不提供多 Agent 栏位或切换功能。

| 控制方 | 功能 |
|---|---|
| Agent | 购买后自动控制角色执行移动、战斗、采集、种田、合成和经济行为；同时作为 OHM Stake 载体 |
| 人类 | 直接控制宠物；拥有 Agent 后，还可以管理 Agent 的 Prompt、Context、Behavior Codes、启停、预算和资产 |

### 2.1 Agent 宠物

- 玩家首次进入时选择自己的宠物形象；形象只影响外观，不改变属性或玩法能力。
- 创建宠物和领取初始装备不要求游戏内付费或 Energy 充值，但玩家钱包需要自行承担链上 Gas。
- 宠物可以执行 Agent 能执行的游戏行为，并遵守相同的位置、能力、资源和链上规则。
- 账户没有 Agent 时，宠物使用最低属性；拥有 Agent 后，宠物的战斗属性取最低属性与该 Agent 的 33% 属性中的较高值，移动范围取 `5` 与该 Agent 移动范围中的较高值。
- 宠物最低属性应能配合初始装备完成普通 Lv1 战斗、采集和种田，但不保证能够完成精英、Boss 或其他高难度对象。
- 宠物始终拥有容量为 2 的独立背包，不继承 Agent 的背包容量；所有物品默认单件重量为 1。
- 玩家首次创建宠物时获得 Lv1 剑、斧头和水壶。
- 初始装备与账户绑定，不能交易、借贷或作为装备升级材料。
- 初始装备保存在装备栏，不占用宠物背包容量。

### 2.2 Agent 配置

玩家购买并绑定的唯一 Agent 包含以下可配置内容：

- System Prompt
- Context
- Behavior Codes
- 性格参数

性格使用五个 `0–100` 参数：风险偏好、目标专注、探索倾向、合作倾向和资源谨慎。参数只影响决策权重和 Prompt，不影响链上数值。

## 3. 核心循环与成长

```text
Agent 自动执行 / 人类通过宠物手动执行
→ 战斗、采集或种田
→ 没有 Agent：产出进入未激活背包
→ 拥有 Agent：支付游戏成长 Energy 后激活产出
→ 符合资格时结算 Agent 成长进度
→ 玩家选择保留物品用于合成、交易、装备或借贷，或投入物品兑换 OHM
→ 若 Agent 剩余额度足够，按物品固定值兑换并销毁物品
→ 兑换所得 OHM 自动注回该 Agent，并从下一个 epoch 起增加质押权重
```

### 3.1 Agent 成长

- Agent 不设置用于穿戴、生产或资格判断的角色等级；每个 Agent 只保存一条 Lv1–9 成长阶段与有效成长掉落进度，不按职业拆分。
- 战斗、采集和种田产生的合格有效成长掉落直接累加到同一条进度，成长判定不读取掉落所属职业；当前阶段累计获得 2,000 件后进入下一阶段。
- 每件有效成长掉落计为 1 点进度；阶段提升不消耗物品，也不额外消耗 Energy 或 OHM。
- Agent 从 Lv1 成长至 Lv9 的目标有效生产时间保持为 720 小时。
- 每阶段所需数量固定为 2,000 件；平均获取间隔随成长阶段从 1 分钟逐步增加至 5 分钟。
- 三种玩法通过对象强度、行动时间和基础掉落数量校准获取速度；同成长阶段、典型装备条件下的有效成长掉落速度差距应控制在 10% 以内。
- 成长阶段提升 Agent 的基础 HP、移动范围、行动速度和背包容量，不限制装备，也不直接乘算 OHM 奖励。
- Lv1–Lv9 分别映射到基础 HP `1×–5×`、移动范围 `5–13` 格、行动速度 `1.0×–1.8×`、背包容量 `10–1,000`；完整曲线见数值文档。
- 成长阶段通过扩大移动格数、提高行动速度和使 Agent 更稳定地产出高等级素材，间接提高 OHM 额度兑现速度；装备负责提升对应职业的攻击、防御和暴击等职业数值。

<details>
<summary>有效成长掉落判定</summary>

- 必须由该 Agent 通过战斗、采集或种田实际获得，物品等级必须等于该 Agent 当前成长阶段；物品职业不参与成长判定。
- 只有支付生产 Energy 并完成激活的基础掉落计入；稀有掉落和额外奖励不计入。
- 宠物获得的物品不为任何 Agent 增加进度；购买 Agent 前生成的未激活产出，之后即使激活也不补发成长进度。
- Marketplace 购买、P2P 转入、合成和系统赠送的物品不计入。
- 多人结算只计算最终实际分配给该 Agent 的物品。
- 物品计入后可以交易、合成或消耗，不会扣减已经获得的进度。
- 进入下一成长阶段后进度归零；超过 2,000 件的部分不结转。

</details>

### 3.2 装备

- 每个职业有对应装备和工具，装备提供该职业的攻击、防御和暴击属性。
- Agent 可以穿戴任意等级的装备和工具，成长阶段不作为穿戴门槛。
- 装备可以自由混搭，不要求完整职业套装。
- Agent 的基础 HP、移动范围和背包容量由成长阶段决定；装备不能增加 HP。
- 成长阶段在生产结算完成后更新；最大 HP 随阶段提高，当前 HP 不因阶段提升而恢复。
- 背包按物品数量与重量计算已用容量；所有物品的默认单件重量为 1。
- 只有物品总重量不超过背包容量时才能携带或接收；已穿戴并存放在装备栏的物品不占背包容量。
- 各职业攻击、防御和暴击率由固定职业基础数值与实际装备属性相加得到。
- 装备通过提高对应职业的行动完成效率、素材产出速度和可稳定获取的素材等级产生价值，并由此提高 OHM 额度兑现速度；装备本身不直接乘算 OHM 奖励。
- 绑定的 Lv1 初始装备只提供新手生产资格和对应的 Lv1 有效生产等级，不参与装备经济循环。

## 4. 三职业统一战棋遭遇

战斗、采集和种田统一使用广义的“战斗”机制。三者共用地图、阵营回合、移动、技能、伤害、多人加入和掉落结算，只替换敌方对象、职业属性、武器、技能表现和掉落表。

| 遭遇类型 | 敌方对象 | 唯一武器 |
|---|---|---|
| 战斗 | 怪物 | 剑 |
| 采集 | 采集物 | 斧头 |
| 种田 | 作物或农田对象 | 水壶 |

后续新增或修改战斗相关功能时，必须同时兼容战斗、采集和种田，不为单一类型建立第二套底层机制。

### 4.1 地图与参与对象

- Agent 或人类宠物可以对大地图中的怪物、采集物或农田对象发起遭遇。
- 每场遭遇使用有限长宽的战棋地图；大地图显示的目标数量等于遭遇内生成的敌方对象数量。
- 友方和敌方对象都可以堆叠在同一格，单位堆叠不阻挡移动。
- 怪物可以移动和使用技能；采集物和作物默认不能移动，但可以在敌方回合使用技能攻击。
- 敌方对象不能撤离。

<details>
<summary>多人动态加入</summary>

- 其他玩家的宠物或 Agent 可以动态加入进行中的遭遇；同一人类账户最多由该账户的宠物和唯一 Agent 同时参与。
- 新加入对象统一出生在友方地图边界，并从下一个友方回合开始行动。
- 每个参与对象独立记录伤害、行动和掉落归属；同一账户不合并伤害，也不获得额外随机权重。

</details>

### 4.2 阵营回合

- 遭遇开始时使用协议随机数，以各 `50%` 的概率决定友方或敌方先手。
- 一个完整轮次由一个友方回合和一个敌方回合组成；一方结束后才进入另一方回合。
- 同一阵营的所有对象可以并发决策，决策确认后立即执行，不等待其他对象。
- 多个行动冲突时按协议实际确认顺序执行；链上提交速度影响执行结果属于允许的玩法结果。
- 每个阵营回合最多 60 秒；所有对象完成行动或时间达到上限时结束，未行动对象自动待机。
- “待机”只结束当前对象的行动，任何单一参与者都不能提前结束其他友方对象的回合。

<details>
<summary>对象行动流程</summary>

```text
可选：不限次数更换装备、使用血瓶
→ 可选：在移动范围内移动
→ 攻击或释放技能，或待机/撤离
→ 标记本阵营回合已行动
```

- 更换装备和喝血瓶是免费准备操作，不消耗移动或正式行动，但只能使用该对象实际携带的物品。
- 点击己方对象时显示“移动、攻击、待机”；对象位于地图边界时增加“撤离”。
- 已选择目标在行动确认前死亡时，本次校验失败且对象不记为已行动，可以在剩余时间内重新决策。

</details>

### 4.3 移动与技能

- Agent 的基础移动范围由成长阶段决定，Lv1 默认为半径 5 格，Lv9 为半径 13 格。
- 可移动格满足 `横向距离² + 纵向距离² ≤ 移动范围²`，形成接近圆形的移动区域。
- 技能释放范围和 AOE 半径使用相同的圆形格子距离算法。
- 远程攻击配置在技能上，不增加远程武器类型。
- AOE 永远不会伤害友方，不提供友伤配置。

<details>
<summary>技能配置字段</summary>

| 字段 | 含义 |
|---|---|
| `CastRange` | 施法者到目标对象或目标格的最远距离 |
| `SkillCoefficient` | 技能伤害系数 |
| `EffectRadius` | 目标格周围的效果半径 |
| `IsGridAOE` | 是否按格子范围攻击多个敌方对象 |

- 单体技能选择具体对象；格子 AOE 选择目标格并命中效果范围内的全部敌方对象。
- 多个对象堆叠在同一格时，格子 AOE 可以同时命中这些对象。
- 一次技能可以攻击多个对象，但施法者只消耗一次正式行动。

</details>

### 4.4 死亡、撤离与遭遇结束

- 敌方对象 HP 归零时立即死亡并逐个结算掉落，不等待整场遭遇结束。
- 友方对象 HP 归零时立即退出遭遇，但保留已经造成的有效伤害和后续掉落资格。
- 友方对象移动到地图边界后可以执行“撤离”；撤离后不能重新加入同一场遭遇，但同样保留已有伤害和掉落资格。
- 整场遭遇最多持续 30 分钟；到达上限时完成当前正在执行的行动，不再开启新行动。
- 时间到达后，已死亡对象的掉落保留；仍存活的敌方对象不产生掉落并恢复初始状态，所有剩余参与者退出。
- 行为过程中已经发生的 Gas、Agent 运行和模型调用成本不因死亡、撤离或超时退还。

### 4.5 多人伤害与逐件掉落

- 每个敌方对象独立累计各参与对象对其造成的有效伤害；最后一击只计算不超过剩余 HP 的部分。
- 对象可以配置多个掉落项和数量，生成的每一件物品都按该对象的有效伤害占比独立随机分配。
- 普通掉落允许所有造成有效伤害的对象参与；稀有掉落只允许有效伤害占比不低于 5% 的对象参与。
- 已死亡或撤离的 Agent 仍参与随机；抽中的物品成为遭遇地点的待领取战利品，返回且背包容量足够时领取。
- Agent 背包已满时，抽中的物品同样进入待领取战利品，不重新抽取且不会丢失。
- 宠物抽中的物品直接尝试进入容量为 2 的宠物背包；剩余容量不足时物品直接消失，不重新抽取，并在界面提示容量风险。
- 宠物获得的物品不为任何 Agent 增加成长进度；只有 Agent 自己抽中并满足条件的有效成长掉落才增加该 Agent 的进度。
- 暴击和逐件掉落共用协议随机数来源并使用不同标签，客户端不能提交随机结果。

<details>
<summary>逐件分配示例</summary>

若一个怪物生成木材 ×3 和精华 ×1，则执行四次独立的伤害权重随机，而不是把整个掉落包分给一个参与对象。

</details>

### 4.6 HP 恢复

- 三种遭遇都可能消耗角色 HP。
- 角色可以返回主城免费恢复全部 HP。
- 角色可以在正式行动确认前不限次数使用实际携带的血瓶恢复 HP。

## 5. 玩法模块

### 5.1 战斗

- 普通、精英和 Boss 都使用第 4 节的统一战棋遭遇机制。
- 角色必须装备剑；怪物可以移动并配置单体或 AOE 技能。

### 5.2 采集

- 所有采集对象统一要求斧头，不再区分镐子或镰刀。
- 采集物默认移动范围为 0，可以在敌方回合使用采集技能攻击。
- 采集物 HP 归零后立即逐件结算掉落。

### 5.3 种田

- 所有农田对象统一要求水壶，不再使用锄头。
- 种田不包含锄地、待浇水、成长、成熟或等待收获等中间状态。
- 作物默认移动范围为 0，可以在敌方回合使用种田技能攻击。
- 作物 HP 归零后立即逐件结算掉落并重置。

### 5.4 合成

- 每个职业、每个等级固定有三种不同的基础素材；三种素材各 1 件合成 1 份同职业、同等级精华。
- 每件职业装备都依赖另外两个职业的同等级精华各 1 份，不设置 Lv1 特例。

| 目标产物 | 固定输入 |
|---|---|
| 战斗精华 | 同等级三种不同战斗素材各 1 件 |
| 采集精华 | 同等级三种不同采集素材各 1 件 |
| 种田精华 | 同等级三种不同种田素材各 1 件 |
| 战斗装备 | 同等级采集精华 1 份 + 种田精华 1 份 |
| 采集装备 | 同等级战斗精华 1 份 + 种田精华 1 份 |
| 种田装备 | 同等级战斗精华 1 份 + 采集精华 1 份 |

- Lv1 装备直接使用两种精华合成；Lv2 及以上装备还必须投入同职业、同槽位的上一等级装备。
- 合成成功后，材料和用于升级的旧装备在同一笔结算中销毁，产出 1 件目标物品。
- 合成必须在工作台允许的交互距离内执行。
- V1 使用固定配方和 100% 成功率；执行合成不额外消耗 Energy。
- 合成不增加 Agent 成长进度。合成销毁配方输入并生成目标物品；产物按固定配方继承可验证的名义累计 Energy，用于计算其固定 OHM 兑换值，但该数值不是 Marketplace 价格、协议回收底价或借贷估值。
- 已经投入 OHM 兑换并销毁的物品不能再参与合成；精华或装备只有在其全部配方输入均未被兑换时才能生成，避免同一份 Energy 成本重复兑现。

## 6. 产出与 Energy

### 6.1 生产结算

- 生产 Energy 按逐件随机后实际归属的掉落物计算，只在该物品完成激活时扣除。
- 生产和 Agent 运行消耗的 Energy 只是游戏成长成本，不进入国库的 OHM mint 额度。已激活物品按固定公式记录名义累计 Energy 与协议 OHM 兑换值；该值只用于消耗 Agent 已有额度，不代表物品市价，也不会自行生成额度。
- 只有已激活且归属 Agent 本人的合格基础掉落才结算 Agent 成长进度；基础材料、精华和非绑定装备均可由拥有者主动投入兑换 OHM。
- 兑换按物品固定 OHM 值扣减 Agent 未兑换额度，并在同一笔结算中销毁物品。基础材料和精华可以按整数数量部分成交；装备必须整件兑换，剩余额度不足时不得销毁或部分兑换装备。
- 兑换所得 OHM 不直接进入玩家可用余额，而是自动注回同一 Agent，并从下一个 30 分钟 epoch 起增加质押权重。
- 角色死亡或撤离不取消已记录的掉落资格；未生成、未分配或因宠物背包容量不足而销毁的物品不扣除生产 Energy。
- 遭遇超时时，已经死亡对象的逐件掉落正常保留，仍存活对象不产生生产结算。
- 物品、掉落率、Energy 成本、Energy 保留率、物品固定兑换值和 epoch 额度统一参考数值文档。

### 6.2 待激活与待领取产出

- 账户没有 Agent 时，宠物获得的物品默认以未激活状态进入宠物背包，不扣除生产 Energy，也不获得成长进度或 OHM。
- 账户拥有 Agent 但生产 Energy 不足时，产出同样进入未激活状态。
- 待激活记录保存物品、数量、Energy 欠额、所属职业和原始行动信息。
- 待激活物品使用单独背包 Tab，可以丢弃，但不能交易、合成或参与其他经济行为；已激活与未激活物品共同占用宠物的容量 2。
- 宠物普通背包容量始终固定为 2；逐件掉落归属宠物后再校验容量，容量不足时该件物品消失且不重新抽取。
- Agent 已死亡、撤离或背包容量不足时，抽中的物品保存在遭遇地点的待领取战利品中；归属不会改变，该 Agent 返回且背包容量足够后领取。
- 购买 Agent 后，玩家可以支付生产 Energy 激活购买前获得的物品；这些历史物品不补发 Agent 成长进度，但激活后可以像普通物品一样主动投入 OHM 兑换。
- Agent 自己获得的未激活物品，在之后支付生产 Energy 时可按原资格结算成长进度并获得正常兑换资格。宠物获得的物品即使激活也不增加 Agent 成长进度，但可以进入普通合成、交易与 OHM 兑换流程。

### 6.3 运行 Energy

- 所有账户都可以充值 Energy 并参与抽奖式 Bond，不以是否拥有 Agent 为前置条件。
- 账户没有 Agent 时，宠物手动操作产生的链上 Gas 由玩家钱包直接支付，协议不提供 Gas 补贴；宠物产出仍按第 6.2 节进入未激活状态。
- 购买 Agent 后开放 Agent 运行 Energy 管理入口；Agent 自动操作使用不可透支的预付运行 Energy 池。
- Agent 的 Energy 余额不足时，在下一收费点或安全行动边界暂停。
- Agent 模式只展示 Energy 消耗、余额、预算和预计续航；宠物手动签名时展示钱包 Gas 需求和余额不足提示。
- `1 Energy = 1 MON`，Energy 由官方统一销售，不能在 Marketplace 中交易。

### 6.4 主城仓库

- 主城提供仓库，仓库容量无限。
- 仓库归属人类账户；宠物是该账户的人类控制入口，同一账户下的宠物和唯一 Agent 共享仓库物品。
- 查看仓库清单可以远程进行；存入和取出必须由宠物或 Agent 到达主城仓库的交互距离内完成。
- 仓库物品不能跨地点直接用于生产、合成或穿戴；使用前必须先取出并由执行角色携带。
- 存取必须原子结算并校验可用数量与角色背包剩余容量，避免同一物品被宠物与 Agent 重复使用。
- 未激活产出不能存入仓库；完成激活后才能作为普通物品存入。

## 7. 经济模块

### 7.1 Energy 路由与国库记账

- MON 按 `1 MON = 1 Energy` 充值；Energy 不可交易，不能直接兑换为 OHM 或质押权重。
- 用于游戏行为、Agent 运行和装备成长的 Energy 是纯游戏消耗，不进入 OHM mint 额度。
- 只有抽奖消耗的 Energy 被视为 Bond 购买资产；对应 MON 从充值储备账本全额划入 Bond 国库账本。游戏成长 Energy 对应的 MON 不进入该账本。
- 每笔 Bond 单独计算 `LotteryBondProfit = LotteryEnergySpent - BondOHMPayout`。该利润只生成未铸造的 OHM 待分配额度；实际 OHM 在抽奖 payout 或 Agent 物品兑换结算时才铸造。

### 7.2 抽奖式 Bond

- 一次抽奖严格对应一次 Bond 购买：投入 `X` Energy，按 Bond 定价获得随机数量 `Q` OHM。
- `Q` 当场铸造并计入总供应，先锁入 depository；只有已解锁 OHM 才能卖出或注入 Agent。
- `Q` 的数学期望必须等于同笔确定性 Bond 的 payout，随机只在玩家之间重分配结果，不改变长期总发放量。
- Bond 使用 Token/MON 的 4 小时 TWAP、1 MON 固定地板和随时间衰减的需求计数器定价；详细曲线见数值文档。
- 抽奖档位、概率、数量和地板钳位必须经过期望配平，不允许因最大 payout 钳位而暗中降低 Bond 期望。

### 7.3 Agent Stake 与 30 分钟 epoch

- 只有已解锁 OHM 可注入 Agent。注入量是该 Agent 的 Stake 本金，也是分配 OHM 额度的唯一直接权重。
- 每个额度 epoch 固定为 30 分钟。本 epoch 发生的注入、自动复投或退出请求于下一个 epoch 边界生效，因此本 epoch 内的分配权重和可兑换额度保持固定。
- Bond 利润进入全局待分配池，使用 8 小时半衰期的指数平滑曲线，每 30 分钟只释放待分配池的一部分。
- 退出税是已经铸造的 OHM，在退出生效后的下一个 epoch 全额补充全局可分配额度；它与未铸造 Bond 额度在账本中分开，在 Agent 侧可以合并展示为本期新增额度。
- 每个 Agent 按 `Agent 有效 Stake / 全局有效 Stake × 本期可分配 OHM` 获得新额度。本期可分配 OHM 包含本期释放的 Bond 额度与本期生效的退出税额度；当前 epoch 未兑换完的额度结转到下一 epoch。
- Agent 发起退出时，对应 Stake 从下一个 epoch 起停止获得 OHM 额度；未兑换额度按退出比例和账本来源退回对应全局池，剩余部分继续绑定在该 Agent。
- 若全局生效 Stake 为 0，本 epoch 不释放 OHM，全部利润额度继续留在待分配池。

### 7.4 Shadow 式线性退出

- 玩家可以选择立即退出，或选择 `7–30 天`的线性退出期；退出期最终按 30 分钟 epoch 对齐。
- 立即退出扣除退出本金的 `50%`；线性退出在 7 天时同样为 `50%`，此后随等待时间线性下降，30 天时为 `0%`。
- 退出请求一经确认不可取消。净到账 OHM 进入退出托管，到期后转为钱包可用余额；退出队列中的 OHM 不再获得 epoch 额度或物品兑换权。
- 退出罚金不进入协议收入，也不 mint 或 burn。退出本金全部从有效 Stake 分母移除，罚金进入独立的已铸造 OHM 额度池，并在下一个 epoch 按退出后的有效 Stake 快照补充给留存 Agent。
- 例如 A 立即退出 `100 OHM`，A 获得 `50 OHM`、退出税额度增加 `50 OHM`、全局 Stake 分母减少完整的 `100 OHM`。若退出前全局 Stake 为 `S`、本期 Bond 额度为 `B`，留存用户 i 的新增额度为 `Stake_i / (S - 100) × (B + 50)`；不能同时使用 `S - 50` 作为分母并把 `50` 再加入额度池。
- 退出税额度只能通过投入物品逐步兑换；兑换所得 OHM 自动复投并继续受同一退出规则约束。若退出后全局有效 Stake 为 0，罚金留在独立池中，等待出现有效 Stake 后再分配。

### 7.5 投入物品兑换 OHM 与自动复投

- Agent 在 epoch 开始时获得 `本期总可用额度 = 历史未兑换额度 + 本期新增额度`。历史额度只提高可兑换余额，不会放大单件物品的 OHM 价值。
- 基础材料每级生产 Energy 按 `1、2、4、8、…、256` 逐级翻倍；Energy 保留率从 Lv1 的 `50%`按指数曲线增长到 Lv9 的 `100%`。
- 基础材料固定兑换值为 `单件生产 Energy × 当前等级保留率`；精华按三件同级基础材料的累计 Energy 计算；装备按固定升级配方包含的全部历史 Energy 计算。
- 投入物品时必须先检查 Agent 剩余额度。结算成功后销毁物品、等额扣减额度，并把获得的 OHM 自动复投到同一 Agent，从下一个 epoch 生效。
- 单件兑换值不读取 Agent 的历史额度、Stake 数量或 Marketplace 价格。等待只会积累额度，不会提高同一件物品的兑换值；成长通过产量、可获得的物品等级以及高等级 Energy 保留率提高实际兑换效率。

### 7.6 单件装备 P2P 借贷

- 一件装备同时只能担保一笔贷款。
- 成交后装备进入托管；借款人可以继续使用，但不能交易、转移或再次抵押。
- Lender 设置本金、最高 LTV、APR 和期限，成交后不能单方面修改。
- 利息从本金发放后按时间累计，提前还款不收额外费用。
- 宽限期结束后可以清算，抵押装备归 Lender 所有。
- 协议只对实际支付或已收取的利息收费。

### 7.7 Marketplace、P2P 与位置

- 资金操作可以远程发起。
- Marketplace 支持远程买入；物品保存在 Marketplace，角色到达后才能 Claim。
- 卖出成交后立即获得 MON。
- P2P 交易要求双方处于允许距离内，并进行原子结算。
- 物品不能跨地点瞬移；角色必须携带生产和合成所需物品，Agent 之间通过主城共享仓库存取物品。
- 背包、仓库、资源对象、工作台、Marketplace 和 P2P 都需要验证位置或交互距离。
