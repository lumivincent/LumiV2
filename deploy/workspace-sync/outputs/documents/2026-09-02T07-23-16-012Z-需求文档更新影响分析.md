# 需求文档更新影响分析

以下仅基于本次文档增删的变化分析。

## 一、已确认的产品变化

### 1. 从「一人一 Agent」改为「一宠物、多 Agent」
**已确认产品事实**

- 每个账户仍只有一个人类宠物，宠物仍是人类手动控制入口。
- 账户可购买、绑定并持有多个 Agent；多个 Agent 可同时绑定同一宠物，并通过 Agent 栏位切换管理。
- 原先的协议级“一人一 Agent”限制被移除。
- 每个 Agent 都是独立行动与资产单元，分别拥有：
  - 成长阶段；
  - 装备；
  - 背包；
  - Prompt / Context / Behavior Codes / 性格；
  - 运行状态；
  - OHM Stake。
- 多个 Agent 不会同时控制宠物；宠物始终由玩家直接控制。
- 账户级 Energy 池与主城仓库在同一宠物绑定的所有 Agent 间共享。

**产品意义**

产品从“玩家拥有一个可成长 AI 角色”，扩展为“玩家围绕一个宠物入口，管理多个分工明确的 AI Agent”。这使 Agent 栏位、组合、分工和多角色协作成为正式系统，而不再只是后续可能性。

---

### 2. 宠物属性继承改为「进场选源 + 本场锁定」
**已确认产品事实**

- 无 Agent 时，宠物使用固定最低属性。
- 有多个 Agent 时，玩家必须在宠物进入遭遇前，选择一个已绑定 Agent 作为该场遭遇的属性来源。
- 宠物不会叠加多个 Agent 的属性，也不会在多个 Agent 中逐项取最高属性。
- 遭遇开始后，来源 Agent 锁定至本场结束；即使中途切换 Agent、换装或 Agent 成长，也不会刷新宠物本场属性。
- 宠物属性规则为：
  - 战斗属性：`max(宠物最低属性，来源 Agent 对应属性的 33%)`
  - 战棋移动范围：`max(5，来源 Agent 战棋移动范围)`

**产品意义**

这明确避免了多 Agent 带来的“属性拼装”或“多角色叠加养成”问题。宠物是一个手动入口，不是多 Agent 属性的聚合器；玩家需要为每次遭遇选择一名“本场代理人”。

---

### 3. 无 Agent 宠物的最低属性被数值化，且新手能力预期下调
**已确认产品事实**

宠物最低属性现在明确为“Lv1 Agent 穿戴对应职业六件 Lv1 满套最终属性的 10%，向下取整”：

| 属性 | 宠物最低值 |
|---|---:|
| 最大 HP | 60 |
| 战斗攻击 / 防御 | 15 / 5 |
| 采集攻击 / 防御 | 15 / 5 |
| 种田攻击 / 防御 | 15 / 5 |
| 暴击率 | 0% |

同时，旧表述“最低属性应能配合初始装备完成普通 Lv1 三类玩法”已删除，替换为：

- 最低属性仅保证无 Agent 状态下可进入游戏；
- **不保证**宠物可独自完成普通 Lv1、精英、Boss 或其他高难度对象。

**产品意义**

免费宠物入口仍保留，但从“可独立完成 Lv1 基础循环的试玩入口”，变成“可进入、体验和参与世界，但不承诺单人稳定完成基础生产目标”的入口。Agent 的价值和必要性因此更明确。

---

### 4. 成长与移动范围的定义进一步收紧
**已确认产品事实**

- Agent 成长带来的移动范围，统一明确为**遭遇战棋阶段的一次移动半径**。
- Lv1–Lv9 的范围仍为半径 5–13 格。
- 该属性不代表：
  - 大世界移动速度；
  - 跑图距离；
  - 寻路范围；
  - 探索效率。
- 成长阶段提升的是 Agent 的基础 HP、战棋移动范围、行动速度和背包容量；装备不增加 HP。
- 成长提高 OHM 额度兑现效率是间接结果：提高遭遇内移动、行动效率及稳定获取高等级素材的能力；装备则负责职业攻击、防御、暴击等数值。

**产品意义**

此前“移动范围”容易被理解成开放世界探索或自动化效率能力。本次明确将其限定为战棋遭遇内能力，避免将成长叙事误导为“大世界跑图更快”或“自动探索半径扩大”。

---

### 5. 同账户多单位可共同参与遭遇
**已确认产品事实**

- 其他玩家的宠物或 Agent 可以动态加入遭遇。
- 同一账户的宠物与多个已绑定 Agent，也可以分别作为独立对象参与同一遭遇。
- 仍受该遭遇的通用参与数量上限限制。
- 各参与对象独立记录伤害、行动和掉落归属；同账户不合并伤害，也不获得额外随机权重。

**产品意义**

多 Agent 不只是后台资产或多套配置，也可以成为可并行参与协作玩法的独立游戏对象。与此同时，参与上限与独立结算规则限制了同账户多 Agent 直接放大单场掉落权重的空间。

---

## 二、对运营叙事和已有内容的影响

## 1. 核心叙事应从「拥有你的 Agent」升级为「组建你的 Agent 队伍」
**运营解释 / 建议**

旧叙事若强调“一个宠物 + 一个终身绑定 Agent”，现在已不准确。更适合的框架是：

- 宠物是玩家的统一身份、手动入口和账户归属；
- Agent 是可购买、可配置、可独立成长与质押的自动化行动单元；
- 多个 Agent 可以围绕同一宠物形成不同分工、装备方向和经济策略；
- 但宠物每场遭遇只继承一名预先选择的来源 Agent，不会获得多 Agent 叠加增益。

可用表达方向：

> 一个宠物，多个可独立成长与执行的 Agent。  
> 你可以管理不同 Agent 的装备、策略、背包与 Stake，并让它们作为独立单位参与 Lumiterra 的世界。

应避免把多 Agent 说成“多倍宠物战力”或“多 Agent 属性融合”。

---

## 2. 免费进入游戏的叙事要从「可完整试玩基础生产」调整为「低门槛进入与体验」
**运营解释 / 建议**

由于“无 Agent 宠物可完成普通 Lv1”的保证已删除，以下旧类表达需要停止使用：

- “不买 Agent 也能稳定完成 Lv1 生产循环”
- “免费宠物可独立刷完 Lv1 基础内容”
- “初始宠物可无门槛完成战斗、采集、种田”

建议改为更准确的说法：

> 所有玩家都可以免费创建宠物进入世界并手动体验玩法；Agent 是后续解锁自动执行、独立成长与 Stake 能力的核心单位。  
> 无 Agent 宠物提供基础进入能力，但不承诺独自完成所有 PvE 或生产对象。

这会使免费入口更真实，也减少玩家因实际战斗效率与预期不符而产生的落差。

---

## 3. Agent 的商业价值从「自动化」扩展为四层价值
**运营解释 / 建议**

本次改动后，Agent 的价值可拆为：

1. **行动价值**：自动执行移动、战斗、采集、种田、合成及经济行为；
2. **成长价值**：每个 Agent 独立成长，获得更高 HP、战棋移动范围、行动速度和背包容量；
3. **策略价值**：不同 Agent 可配置不同 Prompt、Context、Behavior Codes、性格、装备和运行策略；
4. **经济载体价值**：每个 Agent 独立保存 OHM Stake 和可兑换额度执行路径。

但对外不宜把第 4 点写成收益保证。应始终使用“资格、权重、额度、可兑换路径”等产品描述，而非“购买 Agent 即获得回报”或“多买多赚”。

---

## 4. 内容系统需要补上「多 Agent 管理」视角
**运营解释 / 建议**

已有内容若围绕单 Agent 教程、单角色成长或单背包管理构建，需要更新为账户—宠物—Agent 的三级结构：

| 内容模块 | 原有重点 | 本次后应补充 |
|---|---|---|
| 新手引导 | 创建宠物、购买唯一 Agent | 宠物免费进入、首个 Agent、后续 Agent 栏位与管理 |
| Agent 教程 | 单 Agent 配置 | 多 Agent 的独立配置、启停、预算、背包、装备、Stake |
| 战斗教学 | 宠物继承 Agent 属性 | 入场前选择来源 Agent；来源锁定；不叠加、不取最高 |
| 成长教学 | Agent 升级与移动范围 | 移动范围仅限遭遇战棋，不影响大世界探索 |
| 仓库说明 | 宠物与唯一 Agent 共享 | 宠物与同账户所有 Agent 共享，但取用仍需到主城交互 |
| 多人玩法 | 跨玩家加入 | 同账户宠物与多个 Agent 也可独立参战，但受人数上限约束 |

---

## 5. 需要重新审视“多 Agent = 更多产出”的社区预期
**运营解释 / 建议**

多个 Agent 是独立行动对象，因此用户自然会推导出更多并行行动和更多物品产出机会。运营内容必须同步强调系统边界：

- Agent 各自有独立背包、成长、装备、运行状态和 Stake；
- Energy 池是账户共享的，不是每个 Agent 自动获得独立预算；
- 主城仓库虽共享，但存取受地点与背包容量约束；
- 同场遭遇中仍有通用参与人数限制；
- 掉落以每个参与对象的有效伤害独立结算，同账户不会合并伤害或获得额外随机权重；
- 宠物属性只能选定一名来源 Agent，不能聚合多个 Agent。

这有助于防止“买多个 Agent 就是无上限复利/无成本刷资源”的误读。

---

## 三、仍需团队确认的事项

以下不是本次文档已确认的结论，而是多 Agent 落地后仍建议团队明确的事项。

### 1. Agent 栏位和购买规则
**仍需团队确认**

- 初始可持有多少个 Agent？是否存在默认免费栏位？
- Agent 数量是否有账户上限、阶段性上限或其他风控限制？
- 新增 Agent 的购买方式、定价、支付资产和是否存在二级流通机制是什么？
- Agent 是否可以解绑、更换宠物归属、转让或销毁？
- 若未来允许迁移，成长、装备、背包、Stake、未兑换额度和退出请求如何处理？

---

### 2. 多 Agent 的并行运行和共享 Energy 调度
**仍需团队确认**

文档已确认 Energy 池账户共享、Agent 运行状态独立，但尚未明确：

- 多个运行中 Agent 同时触发收费时，Energy 的扣费优先级如何确定？
- 是否支持 Agent 级预算、账户级总预算、每日/每周期上限？
- Energy 不足时，所有 Agent 同时暂停，还是按优先级逐个暂停？
- 用户是否可为某个 Agent 预留或锁定部分 Energy，避免被其他 Agent 消耗？
- 多 Agent 同时操作仓库、工作台、Marketplace 或 P2P 时，除原子校验外，前端如何提示冲突与失败原因？

---

### 3. 宠物选择来源 Agent 的交互与异常处理
**仍需团队确认**

- 宠物是每次进入任何遭遇都必须手动选择来源 Agent，还是可设置默认来源？
- 若来源 Agent 处于运行中、死亡状态、撤离状态、背包满、退出请求中或 Stake 为零，是否仍可作为宠物属性来源？
- 若来源 Agent 在宠物遭遇过程中发生资产变化、成长变化或开始退出，锁定规则如何在 UI 和链上状态中展示？
- 宠物能否选择未携带当前职业装备的 Agent 作为来源？若可以，宠物的“对应属性”具体按何种装备状态读取？
- 宠物本场的 HP 上限发生锁定后，当前 HP、血瓶恢复上限与来源切换禁用提示如何呈现？

---

### 4. 无 Agent 宠物的可玩性与新手路径
**仍需团队确认**

本次已不再承诺无 Agent 宠物能完成普通 Lv1 内容，但仍需要明确体验目标：

- 无 Agent 宠物能否对普通 Lv1 三类对象造成有效伤害，并在什么情况下可能完成？
- 是否存在专门为无 Agent 玩家设置的低难度对象、协作入口或教学目标？
- 初始剑、斧头、水壶与最低属性组合下，预期的失败率、完成时间和资源获得体验是什么？
- 宠物容量仅为 2，未激活物品也占用容量；新手如何理解、处理或避免背包满导致掉落消失？
- 是否希望免费玩家主要体验操作、社交与协作，还是仍应能够完成有限的基础资源循环？

这部分尤其影响新手转化、社区口碑及“免费进入”是否被理解为“免费可玩”。

---

### 5. 同账户多单位进入同一遭遇的限制
**仍需团队确认**

- “通用参与数量限制”的具体人数是多少？
- 同账户宠物与多个 Agent 同场时，是否有账户级席位上限？
- 多个 Agent 是否可以由同一用户同时自动决策并链上提交？
- 同账户单位的出生位置、行动顺序、撤离策略是否有额外限制？
- 如何防止单账户多 Agent 在低难度对象上形成过强的占位、抢怪或资源控制能力？

---

### 6. 多 Agent 经济呈现与风险说明
**仍需团队确认**

- 用户界面是按 Agent 展示 Stake、额度、已兑换量和退出状态，还是同时提供账户汇总视图？
- 共享仓库中的物品被某个 Agent 取出并用于兑换时，如何避免用户误以为这是“账户公共额度”？
- 多 Agent 分别持有 Stake 时，是否允许一键查看全部 Agent 的退出影响、锁定状态和可用额度？
- 多 Agent 的账户行为是否需要额外反女巫、反脚本或资源滥用策略？

---

## 四、需要调整的公开表达

## 1. 必须停止使用的表述

以下表达已与最新产品事实冲突：

- “每个账户只能拥有一个 Agent”
- “一人一 Agent 是协议级限制”
- “宠物绑定唯一 Agent”
- “宠物自动继承唯一 Agent 的属性”
- “拥有多个 Agent 时，宠物取所有 Agent 的最高属性”
- “多个 Agent 的属性会叠加到宠物”
- “无 Agent 宠物可以完成普通 Lv1 战斗、采集和种田”
- “成长提高大世界移动速度、探索距离、寻路范围或跑图效率”
- “同账户最多只能让宠物和一个 Agent 同时参与遭遇”
- “宠物和唯一 Agent 共享仓库”

---

## 2. 建议采用的准确表述

### 角色与 Agent

> 每个账户拥有一个宠物，并可绑定多个独立成长和运行的 Agent。宠物是人类手动控制入口；每个 Agent 都拥有独立的装备、背包、成长、配置、运行状态和 OHM Stake。

### 宠物属性来源

> 宠物进入遭遇前可选择一名已绑定 Agent 作为本场属性来源。该选择在本场遭遇内锁定，多个 Agent 的属性不会叠加，也不会逐项取最高。

### 免费进入

> 玩家可以免费创建宠物并进入游戏。Agent 将解锁自动执行、独立成长、独立背包与 Stake 载体等能力。无 Agent 宠物具备基础进入能力，但不保证可独自完成所有遭遇或生产对象。

### 成长与移动

> Agent 成长提高基础 HP、遭遇战棋内的移动范围、行动速度和背包容量。战棋移动范围不等同于大世界移动、跑图或探索效率。

### 多 Agent 协作

> 同一账户的宠物和多个 Agent 可作为独立对象参与遭遇，但需遵守遭遇参与上限，并分别按实际行动与有效伤害结算。

### 经济相关

> 每个 Agent 独立持有 Stake 与额度执行状态；多个 Agent 不代表属性合并，也不构成任何固定经济结果或 Token 回报承诺。

---

## 五、可复用的一句话结论

**已确认结论：Lumiterra V2 从“一宠物绑定唯一 Agent”的单 Agent 模式，升级为“一个宠物入口管理多个独立 Agent”的多 Agent 模式；同时通过宠物单一属性来源锁定、共享 Energy 与仓库、独立成长与 Stake，以及遭遇人数限制，避免多 Agent 被理解为宠物属性叠加或无边界收益放大。**
