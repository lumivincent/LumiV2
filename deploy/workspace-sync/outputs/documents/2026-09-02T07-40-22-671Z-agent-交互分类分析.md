# Agent 交互分类分析

以下仅分析“Agent 交互”最新完整原型（版本 `f2c1caf973d2`）。这里的“已确认”仅指原型代码中已明确呈现或可操作，不代表已成为正式产品需求。由于本轮未提供产品需求文档和数值文档，无法确认两者是否一致。

## 1. 原型中已确认的界面、流程与规则

### 界面与信息架构

- 一个账户可切换管理多个 Agent。
- Agent 独立展示：状态、位置、任务、成长、装备、背包和 OHM Stake。
- 账户级共享展示：Energy 池、主城仓库。
- 主要界面包括：
  - 我的 Agent／住所
  - OHM 挖矿
  - 成长
  - 主城仓库
  - Agent 设置
  - 异步通话
  - 大世界现场交互

### 已实现的交互流程

- 切换 Agent 后，成长、任务、Stake、背包等内容同步切换。
- 可为共享 Energy 池充值；原型充值按钮直接增加 Energy。
- 可为当前 Agent 注入 OHM：
  - 从钱包余额扣除；
  - 进入待生效变更；
  - 原型提示下一 epoch 生效。
- 可为当前 Agent申请撤出 Stake：
  - 支持立即退出和线性退出；
  - 创建退出记录后进入待处理状态；
  - 原型表达为下一 epoch 进入不可取消队列。
- 可选择仓库材料及数量兑换 OHM：
  - 校验库存和可兑换额度；
  - 成功后销毁材料并扣减额度；
  - 所得 OHM 进入自动复投。
- 可查看仓库、Agent 背包、装备属性与返程记录。
- 可暂停 Agent，调整陌生人交流、P2P 提案、稀有物品确认等授权。
- 可向当前 Agent 发送文字或语音留言；会话可缩小，回复异步到达。
- 大世界靠近其他 Agent 后可建立异步会话。
- 对话可产生 P2P 交换提案；本方签名后显示等待对方钱包签名。
- 可发出召回指令，原型反馈为在“安全行动边界”返程。

### 原型明确表达的规则

- Energy 为账户共享，未暂停的 Agent 从同一余额持续消耗。
- Stake、成长和 OHM 挖矿按 Agent 分开管理。
- 新增 Stake 从下一 30 分钟 epoch 开始影响额度。
- 材料兑换价值在原型中按物品固定值计算，不读取市场价格、Stake 或历史额度。
- 材料兑换成功后销毁物品，并消耗当前 Agent 的可兑换额度。
- 兑换所得 OHM 自动复投，下一 epoch 生效。
- 退出队列从下一 epoch 起停止获得额度及物品兑换权；原型文案称请求不可取消。
- 成长只统计同阶段、已激活的基础掉落；稀有奖励、交易或转移物品不计入。
- Agent 外出时，背包可以查看，但不能远程取回或放入物品。
- 现场聊天不打断探索、采集和移动。
- 文字与语音进入同一个连续会话。

注意：30 分钟 epoch、退出税率、固定兑换值、成长属性等均只是原型内配置，不能据此视为正式确认数值。

## 2. 对产品与运营可能产生的影响

由于缺少正式需求和数值文档，以下均为运营解释或建议，不是差异结论。

- “共享 Energy、独立 Stake”的双层结构有助于形成多 Agent 经营感，但会显著增加用户理解成本。运营教育需要反复说明哪些资源属于账户、哪些属于单个 Agent。
- 多 Agent 同时消耗共享 Energy，可能推动充值和日常管理，也可能让用户产生“后台持续扣费”的焦虑。需要清晰展示消耗速度、预计续航及各 Agent 的消耗贡献。
- Stake 决定额度、材料才能完成兑换、所得又自动复投，形成较强的复合经济循环。若正式规则一致，运营内容必须避免将其简化为固定收益或被动收益承诺。
- 退出税、退出期、停止获得额度和不可取消队列会显著影响用户对流动性的判断。任何公开传播都应在操作前完整披露，而不能只突出收益或复投。
- 固定材料兑换值若与市场价格脱钩，可能影响玩家对采集路线、材料稀缺度和交易价格的判断，也可能产生套利或“系统定价压过玩家市场”的认知。
- Agent 的异步交流、性格与自主决策能够强化陪伴感和人格化叙事，但用户可能误以为 Agent 具有超出实际能力的长期记忆、推理或自主执行权限。
- 对话产生 P2P 提案有较强社交传播潜力，但也会把聊天、资产授权、诈骗防范和钱包签名连接在一起，运营上需要明确安全边界。
- 返程记录、决策依据和成长结算有利于构建可解释性，可成为留存内容；前提是正式系统中的数据真实可追溯，而非仅展示结果文案。

## 3. 用户体验或表达风险

- “Agent 独立”与“账户共享”的边界仍不够稳定：仓库共享，但兑换额度属于当前 Agent；背包独立，但外出时不能移动物品，容易误操作或误解。
- “OHM 挖矿”“Stake”“额度”“材料兑换”“自动复投”集中出现，术语链条较长，新用户很难快速理解资产如何流转。
- 原型展示大量精确数字，容易被截图或引用为正式经济参数。
- “MON 1:1 转为 Energy”属于高敏感兑换表达，目前没有正式来源支持，存在被理解为永久固定兑换承诺的风险。
- “立即退出”同时出现“50% 税·下一 epoch”，可能让用户误以为资金立即到账；到账时间和队列生效时间需要拆开说明。
- 线性退出中“7天50%、30天0%”不足以说明中间税率如何计算、何时到账以及是否分期释放。
- “税收补充全局可分配额度”可能被理解为退出用户损失直接补贴其他用户，容易引发公平性和收益性质争议。
- “暂停运行”是否同步停止 Energy 消耗、任务、聊天、Stake 权益等没有完整反馈。
- 授权开关只展示开/关，未解释关闭后对已有会话、待签提案和稀有物品操作的影响。
- “确认并签名”之后实际只是等待另一方签名，缺少资产锁定、撤销、过期、成交与失败状态。
- 召回提示中的“安全行动边界”缺少定义，也没有预计返程时间或不可召回原因。
- MBTI、人格雷达和决策证据可能让用户过度相信人格数值能够稳定预测行为。
- 仓库文案一处称“材料、精华与非绑定装备可以兑换”，但部分物品又显示未配置或不参与结算，需要更明确的可兑换状态。

## 4. 仍需团队确认的问题

### 产品边界

- 多 Agent、共享 Energy、独立 Stake 是否均为正式需求？
- 仓库究竟是完全账户共享，还是存在 Agent 权限、绑定物品或位置限制？
- 电话、现场聊天、语音、人格系统、P2P 提案是否已立项，还是仅为交互探索？
- Agent 暂停、召回及自主决策的实际执行边界是什么？

### 经济与数值

- Energy 的充值资产、兑换比例、消耗公式和余额归零后的行为。
- epoch 是否确定为30分钟，以及 Stake 变更的快照和生效规则。
- 额度的正式计算公式、结转规则和未兑换额度回流机制。
- 材料固定兑换值的来源、调整权限以及与市场交易的关系。
- 自动复投是否强制，用户能否选择领取或取消。
- 立即退出和线性退出的税率曲线、到账方式、排队时间及取消规则。
- 退出税进入全局额度的规则是否正式成立。
- 成长阶段目标、属性倍率、保留率及材料 OHM 值是否与数值文档一致。

### 资产与安全

- P2P 提案由谁生成、是否需要双方确认、资产何时锁定、是否可撤销或过期。
- 陌生人能否诱导 Agent 创建资产提案，以及 Agent 是否拥有任何签名权限。
- 稀有物品确认适用于转移、交易、兑换还是销毁等哪些操作。
- 外出 Agent 的物品为何不能远程操作，返程、死亡或断线时如何处理。

### 表达与运营

- “挖矿”“Stake”“自动复投”“税收补充额度”等术语是否经过法务与合规审查。
- 是否允许公开展示任何收益、额度、税率或固定兑换值。
- 演示 Agent、余额、产出、时间、属性和返程记录应如何标注，避免被误认为正式数据。
- Agent 人格、异步回复和自主决策应如何描述，才能避免夸大智能能力或资产控制权限。
