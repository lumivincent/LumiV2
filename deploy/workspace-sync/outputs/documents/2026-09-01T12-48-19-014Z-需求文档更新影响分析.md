# 需求文档更新影响分析

## 变化摘要

本次更新将 Lumiterra V2 的经济与 Agent 结构从“物品固定财富值 + Token 奖池/回收”的游戏经济，明确重构为“**Bond 利润产生 OHM 待分配额度 + Agent Stake 按游戏产出兑现额度 + 自动复投**”的闭环。

同时，账户模型从可拥有多个 Agent 收紧为协议级的“**一人一 Agent**”。宠物仍是免费的人类控制入口，但不再可被描述为 Agent 的替代成长或收益路径。

---

## 一、已确认产品事实

### 1. 产品经济底层改为 OHM 驱动的 Bond—Stake—产出兑现模型

- Lumiterra V2 明确定位为运行在 Monad 上、由 Agent 主导、以 **OHM 为底层经济资产**的 Fully Onchain 养成放置类游戏。
- 经济结构参考早期 OHM 的 Bond、协议利润和 Stake 机制，但：
  - Stake 的载体是 Agent；
  - 被动 rebase 被替换为需要实际游戏产出才能兑现的 OHM 额度。
- 玩家使用 MON 按 `1 MON = 1 Energy` 充值；Energy 不可交易。
- 每单位 Energy 只能进入两条互斥路径之一：
  1. 游戏成长：Agent 运行、游戏行为、生产与装备成长等消耗；
  2. 抽奖式 Bond：用于获得随机 OHM payout，并形成协议利润。
- **只有抽奖式 Bond** 会产生 Bond OHM payout 和协议利润。
- 游戏成长、生产、Agent 运行与装备成长消耗的 Energy：
  - 是游戏成本；
  - 不进入 Bond 国库记账；
  - 不形成 OHM mint 额度；
  - 不为物品生成固定财富值。

### 2. OHM 的获得、Stake 与游戏产出形成明确顺序

已确认的核心经济路径为：

```text
MON 充值为 Energy
→ 使用 Energy 参与抽奖式 Bond
→ Bond 当场产生并锁定 OHM payout，同时产生未铸造的 Bond 利润额度
→ 已解锁 OHM 注入唯一 Agent
→ Agent 按 Stake 权重获得 epoch OHM 额度
→ Agent 实际产出并当场激活合格基础素材
→ 素材按等级兑现该 Agent 的额度
→ 挖出的 OHM 自动复投至同一 Agent
```

其中：

- 抽奖式 Bond 的随机性只在玩家之间重分配结果，其数学期望需与同笔确定性 Bond payout 对齐。
- Bond payout 当场铸造并锁入 depository；只有解锁后的 OHM 才能卖出或注入 Agent。
- Bond 利润不是即时可领取收益，而是进入全局待分配池，按 epoch 释放给有效 Stake。
- Agent 获得的 OHM 额度不是直接进入可用余额：
  - 必须通过实际产出合格素材来兑现；
  - 实际挖出的 OHM 自动注回同一 Agent；
  - 自动复投从下一个 epoch 起增加 Stake 权重。
- Agent 的 Stake 本金是其分配 OHM 额度的唯一直接权重。
- Agent 等级、装备和 Energy 消耗都不直接放大 Stake 权重或单件素材的 OHM 兑现比例；它们仅通过效率、行动范围、素材等级与产出速度间接影响额度兑现速度。

### 3. 固定财富值、Token 奖池和协议装备回收已被删除

以下旧接口已确认不再存在，且不能作为其他模块的隐含逻辑：

- 固定物品财富值；
- 财富转化率；
- Token 奖池；
- 物品投入奖池获得 Token 权重；
- 装备回收；
- Slow Redeem；
- Fast Redeem；
- 协议回收报价与回收底价；
- 合成财富守恒；
- 游戏成长 Energy 形成 OHM mint 额度。

合成的定义也同步变化：

- 合成只销毁配方输入并生成目标物品；
- 不增加 Agent 成长进度；
- 不记录、继承或转移固定财富值；
- 不生成 OHM；
- 不改变 Agent 未挖额度。

装备经济价值改为由玩家市场和实际游戏效能支撑：

- 装备提升对应职业的攻击、防御、暴击等职业属性；
- 装备可通过提高行动完成效率、素材速度和可稳定获得的素材等级，间接提升 OHM 额度兑现速度；
- 装备不直接乘算 OHM 奖励；
- P2P 借贷继续存在，但不再读取固定财富值或协议回收价。

### 4. Agent 模型收紧为协议级“一人一 Agent”

- 每个人类账户最多只能购买、绑定和持有一个 Agent。
- “一人一 Agent”是协议级约束。
- 不提供多个 Agent 栏位。
- 不提供 Agent 切换功能。
- 同一账户下，宠物和唯一 Agent可以同时参与同一场遭遇。
- 仓库归属于人类账户，由宠物和该账户唯一 Agent 共享。
- 文档中原有的“多个 Agent”“账户最强 Agent”“所有 Agent 共享仓库”等表述已失效。

### 5. 宠物定位进一步明确：免费入口与手动控制入口，不是成长或 OHM 路径

- 所有账户默认没有 Agent，可先免费选择宠物形象进入游戏。
- 宠物形象只影响外观，不改变属性或玩法能力。
- 宠物可执行战斗、采集、种田等游戏行为，并遵守相同位置、能力、资源和链上规则。
- 无 Agent 时：
  - 宠物使用最低属性；
  - 宠物手动操作产生的链上 Gas 由玩家钱包支付；
  - 协议不提供 Gas 补贴；
  - 宠物产出默认进入未激活背包；
  - 不扣生产 Energy；
  - 不获得 Agent 成长进度；
  - 不获得 OHM。
- 所有账户均可充值 Energy 并参与抽奖式 Bond，**不以拥有 Agent 为前置条件**。
- 宠物获得的物品即使之后激活，也不增加任何 Agent 的成长进度或 OHM。
- 购买 Agent 后，可支付生产 Energy 激活购买前获得的宠物历史物品，但不会补发 Agent 成长进度或 OHM。

### 6. Agent 自身未激活产出的规则更精细化

- Agent 在原生产结算中当场完成 Energy 激活的合格基础素材：
  - 可结算成长进度；
  - 在 Agent 有剩余额度时可兑现一次 OHM。
- Agent 自己获得但未在原生产结算当场激活的物品：
  - 后续支付生产 Energy 后，可按原资格结算 Agent 成长进度；
  - 不能补发 OHM；
  - 即使当时 Agent 没有可挖额度，也不能将该素材保留到后续 epoch 再次尝试挖 OHM。
- 一件素材最多执行一次 OHM 兑现。
- 只有基础素材具备 OHM 兑现资格；稀有掉落、额外奖励、合成物、市场购买、P2P 转入与系统赠送均不构成该资格。

### 7. Agent 成长新增行动速度，但仍不直接增加 OHM 奖励

Agent 成长阶段现已确认提升：

- 基础 HP；
- 移动范围；
- 行动速度；
- 背包容量。

此前未列入成长属性的“行动速度”已成为正式成长价值的一部分。

成长仍然：

- 只有一条 Lv1–Lv9 的共享阶段；
- 不按战斗、采集、种田职业拆分等级；
- 不限制装备穿戴；
- 不直接乘算 OHM 奖励；
- 通过移动范围、行动速度、背包容量和更稳定获得高等级素材的能力，间接提高 OHM 额度兑现效率。

### 8. Stake、额度释放与退出机制已定义为产品核心经济规则

- mining epoch 固定为 30 分钟。
- Stake 注入、自动复投与退出请求均在下一个 epoch 边界生效。
- 当期 Agent Stake 权重和可挖额度在 epoch 内保持固定。
- Bond 利润进入全局待分配池，并按平滑机制逐步释放。
- 若全局没有有效 Stake，则本期不释放 OHM，利润额度继续保留在全局待分配池。
- Agent 未挖完的额度可以跨 epoch 结转，但额度不能脱离 Stake 单独持有或转让。
- Agent 发起退出后：
  - 对应 Stake 从下一个 epoch 起停止获得新额度与退出罚金分配；
  - 对应未挖额度按退出比例退回全局池；
  - 退出队列中的 OHM 不再拥有素材挖掘权。
- 退出可选择即时或线性退出期；请求确认后不可取消。
- 退出罚金不属于协议收入，不产生新 OHM，而是分配给符合条件的留存 Stake。
- 获得的退出罚金直接增加对应 Agent Stake，不先进入钱包余额，且继续受同一退出规则约束。
- 为防止临时注入抢占退出罚金，只有持续生效达到规则门槛的 Stake 才有资格参与分配。
- 无合格 Stake 时，已铸造的退出罚金进入独立池等待后续分配，不能与未铸造的 Bond 利润混合。

## 二、对运营叙事与已有内容的影响

### 1. 主叙事应从“AI 自动玩游戏”升级为“把游戏行为接入链上经济闭环”

#### 运营解释或建议

过去仅强调“Agent 主导”“Fully Onchain”“养成放置”，不足以解释新版的差异化。新版更完整的叙事应是：

> Agent 不只是自动执行游戏操作的 AI 角色，也是玩家在游戏经济中的唯一 Stake 载体。  
> 玩家通过实际游戏产出，将 Agent 获得的 OHM 额度逐步兑现，并使兑现结果自动回流到该 Agent 的 Stake 中。

可将叙事拆为三层：

1. **玩法层**：Agent 自动探索、战斗、采集、种田、合成与管理经济行为。
2. **成长层**：Agent 通过持续生产提升行动能力、背包能力与高等级素材获取稳定性。
3. **经济层**：已解锁 OHM 注入 Agent 后形成 Stake 权重；游戏产出决定额度兑现节奏，而不是被动领取。

这样可以避免市场将产品简单理解为“带 Token 的挂机游戏”或“Agent 挖矿工具”。

### 2. “游戏行为创造财富”应改为“游戏行为兑现额度”

#### 运营解释或建议

旧版本的固定财富值叙事容易让玩家理解为：

- 每件物品天然带有可回收价值；
- 生产消耗会沉淀为资产价值；
- 合成、回收与奖池能将物品价值转化为 Token 回报。

这些表达均已不适用。

新版应使用更准确的语言：

- 游戏产出决定 Agent 的成长和额度兑现进度；
- 基础素材的等级影响额度兑现速度；
- 成长和装备提升的是生产效率与素材质量；
- OHM 额度的来源是抽奖式 Bond 所产生的协议利润，而不是游戏 Energy 消耗或物品本身；
- 素材并不“铸造财富”，而是在合格条件下触发 Agent 已获额度的兑现。

应避免：

- “打怪即挖矿”
- “玩得越多就必然获得更多 OHM”
- “每件物品都有内在价值/固定价值”
- “游戏消费会转化为 Token 奖励”
- “装备可保底回收”
- “合成能保存或放大价值”

这些表达会错误描述资金来源、资产性质和经济路径。

### 3. Agent 的购买叙事要从“更多自动化单位”改为“唯一长期身份与经济容器”

#### 运营解释或建议

“一人一 Agent”使 Agent 不再适合被包装为可批量扩张的生产单位。更适合强调：

- 每位玩家拥有一个唯一的长期 Agent；
- Agent 同时承载人格配置、自动化行为、成长进程、装备配置、OHM Stake 与自动复投状态；
- 玩家通过 Prompt、Context、Behavior Codes 与性格参数塑造自己的链上行动者；
- Agent 成长和经济状态是长期连续的，不是多账号、多 Agent 的并行刷量系统。

内容重点可从“买 Agent 提升效率”转为：

- 选择并培养你的唯一 Agent；
- 建立其策略与行为偏好；
- 让游戏表现、装备路线和 Stake 状态共同形成长期进展；
- 人类宠物与 Agent 是同一账户下的两种控制入口，而非两套角色资产。

### 4. 免费宠物入口的转化叙事需要重写

#### 运营解释或建议

旧版“无 Agent 不显示 Energy 充值入口”已被推翻。现在无 Agent 用户也可以：

- 充值 Energy；
- 参与抽奖式 Bond；
- 手动通过宠物体验基础玩法；
- 以钱包自行支付链上 Gas。

但无 Agent 用户的宠物产出：

- 默认未激活；
- 不产生 Agent 成长；
- 不产生 OHM；
- 受固定的小背包容量限制。

因此，免费体验与 Agent 转化应形成明确分层：

| 用户状态 | 可强调价值 | 不应暗示的能力 |
|---|---|---|
| 无 Agent 宠物用户 | 免费进入、手动探索、体验链上战棋玩法、参与 Bond | 可通过宠物积累 Agent 成长或 OHM |
| 已拥有 Agent 用户 | 自动化执行、成长进展、产出激活、额度兑现、资产与策略管理 | 保证获得 OHM 或经济结果 |
| 已 Stake Agent 用户 | 获得与有效 Stake 对应的额度分配资格，并通过游戏产出兑现 | 被动或固定频率的收益 |

转化内容要解释“为什么需要 Agent”，而不是只强调“宠物免费、Agent 付费”：

> 宠物让玩家进入世界；Agent 才让玩家开启自动化、成长记录、产出激活与 Stake 驱动的额度兑现循环。

### 5. 装备内容需要脱离“回收价值”与“财富转化效率”

#### 运营解释或建议

旧内容如包含以下主题，应整体进入待复核或下线队列：

- 装备固定财富值；
- 装备回收；
- 快速回收与慢速回收；
- 协议报价；
- 装备作为奖池筹码；
- 装备提升财富转化率。

新版装备叙事应聚焦：

- 职业能力：攻击、防御、暴击；
- 完成效率：更快完成战斗、采集与种田；
- 素材路径：提高稳定取得更高等级素材的能力；
- 经济间接性：通过效率和素材等级提高额度兑现速度；
- 玩家市场：装备价值由使用效能、交易需求和 P2P 借贷市场共同形成，而非协议回收价锚定。

### 6. 内容中必须区分“OHM payout”“OHM 额度”“已解锁 OHM”“自动复投 OHM”

#### 运营解释或建议

这是本次最容易被误读的经济概念，运营内容和产品 UI 需要统一术语。

| 概念 | 对外解释建议 |
|---|---|
| Bond OHM payout | 抽奖式 Bond 当场产生、先锁定的 OHM |
| 已解锁 OHM | 可卖出或注入 Agent 的 OHM |
| Agent Stake | 注入 Agent、用于决定额度分配权重的 OHM 本金 |
| Agent OHM 额度 | Agent 按有效 Stake 获得、尚需通过合格素材兑现的额度 |
| 素材兑现 OHM | 当场激活的合格素材实际结算出的 OHM |
| 自动复投 OHM | 已兑现、自动回注 Agent，并于后续 epoch 生效的 OHM |

不建议把上述所有状态统一称为“奖励”“收益”“收益率”或“挖矿收入”。这会模糊锁定、兑现、可用余额与自动复投之间的差异，也增加错误预期和合规沟通风险。

## 三、已有内容的复核与下线优先级

### P0：应立即停止使用或修改的公开表达

以下表达与最新产品事实冲突：

- “游戏成长 Energy 会进入 Token 奖池、国库或财富池”
- “生产行为生成固定财富值”
- “物品拥有可回收的固定价值”
- “合成继承、保存或放大固定财富值”

- “协议按装备固定财富值提供回收报价”
- “没有 Agent 不能充值 Energy”
- “购买 Agent 后才可以参与 Bond”
- “一个账户可购买、持有或切换多个 Agent”
- “宠物继承账户最强 Agent 的属性”

### P2：需要补充的新内容

建议新增以下可复用内容模块：

1. **“Energy 两条路径”图解**  
   清晰区分游戏成长消耗与抽奖式 Bond，避免用户认为所有 Energy 都进入经济回报循环。

2. **“从 Bond 到 Agent”的经济流程图**  
   解释 Bond payout、利润待分配池、Stake、额度、素材兑现与自动复投。

3. **“为什么 Agent 是唯一的”说明**  
   解释一人一 Agent 的产品设计：长期身份、策略容器、成长载体和 Stake 容器。

4. **“宠物与 Agent 的区别”对照表**  
   明确免费进入、手动操作、产出激活、成长、OHM 额度与自动化的边界。

5. **“OHM 的不同状态”术语卡**  
   避免用户把锁定 OHM、Stake、本期额度、自动复投和钱包余额混为一谈。

6. **“退出规则与风险”独立说明**  
   退出时间、罚金、不可取消、退出后停止额度与罚金分配资格等内容，需要在操作前清晰披露，而不是仅留在 FAQ。

## 四、公开表达需要调整

### 1. 建议保留并强化的表达

- “Fully Onchain 的 Agent 养成放置游戏”
- “运行在 Monad 上”
- “一个账户，一个长期成长的 Agent”
- “Agent 同时承担自动化执行、成长记录与 Stake 载体的角色”
- “玩家的实际游戏产出决定 Agent OHM 额度的兑现节奏”
- “成长和装备提升游戏效率，而不直接放大 Stake 权重”
- “宠物是免费进入世界的人类控制入口”
- “抽奖式 Bond 与游戏成长 Energy 是两条独立路径”
- “只有已解锁 OHM 可以注入 Agent”
- “挖出的 OHM 自动回注至同一 Agent，并在后续 epoch 生效”
- “装备价值来自职业效能、素材效率与玩家市场需求，而不是协议固定回收价”

### 2. 建议改写的表达

| 旧式表达方向 | 建议调整为 |
|---|---|
| Agent 自动打金 | Agent 自动执行链上游戏行为，并通过合格产出兑现已分配额度 |
| 游戏产出 Token 奖励 | 游戏产出用于推进 Agent 成长，并在满足条件时兑现 Agent OHM 额度 |
| Energy 是挖矿燃料 | Energy 是不可交易的游戏资源；其用途分为游戏成长与抽奖式 Bond 两条互斥路径 |
| 装备提高收益 | 装备提升职业行动效率、素材速度与高等级素材稳定性，间接影响额度兑现速度 |
| 宠物试玩后可补领奖励 | 宠物可免费体验玩法；其历史产出可在拥有 Agent 后激活为普通物品，但不补发成长或 OHM |
| 多 Agent 策略组合 | 单一 Agent 的长期策略、成长、装备与 Stake 管理 |
| 退出可自由赎回 | 可发起退出，但退出路径、托管期、罚金与资格影响需以产品规则为准 |

### 3. 不应作为公开承诺的表达

以下内容即使存在于当前数值文档，也不建议在面向大众的营销内容中作为确定性卖点、回报承诺或收益暗示：

- 固定频率的 OHM 释放结果；
- 用户可获得的 OHM 数量；
- 用户的收益率、回本周期或复利效果；
- 通过升级、装备或自动化可实现的经济结果；
- 特定退出路径的最终到账结果；
- 抽奖式 Bond 的实际中奖结果；
- 任何“保底”“稳赚”“稳定收益”“自动增长”“无风险复利”表述；
- 将示例数值、测试条件或机制参数包装为实际用户收益预测。

## 五、运营风险与应对建议

### 风险 1：用户将“额度兑现”误解为被动 Stake 收益

#### 运营解释或建议

新版机制最关键的区别是：Stake 产生的是 Agent 可兑现额度的分配权，而不是直接发放到钱包的被动收益。

应在所有经济页、Agent 页、Bond 页和新手流程中反复明确：

- Stake 不等于即时可用余额；
- 额度不等于已获得 OHM；
- 兑现依赖合格素材与当场 Energy 激活；
- 已兑现 OHM 自动复投，并非直接可提现；
- 实际结果受 Bond 利润、全局 Stake、产出、素材等级、额度余额、解锁与退出状态等多重因素影响。

### 风险 2：用户误以为游戏成长 Energy 会“回流”成 OHM

#### 运营解释或建议

由于 Energy 同时用于游戏成长和抽奖式 Bond，用户很容易将其理解为统一的“投入—回报”资产。

建议在产品与内容中强制使用路径标签：

- **游戏成长 Energy：游戏成本**
- **抽奖式 Bond Energy：Bond 购买资产**

避免用“充值后 Energy 会进入国库并产生奖励”这类笼统句式。

### 风险 3：免费宠物入口可能产生“付费后补算”的错误预期

#### 运营解释或建议

无 Agent 用户可充值 Energy、参与 Bond、手动体验玩法，但宠物产出不产生成长和 OHM。这一设计需要在首日体验中提前说明，否则用户可能认为购买 Agent 后可以追溯领取此前游戏贡献。

建议在宠物背包、未激活物品和 Agent 购买页加入一致提示：

- 宠物历史物品可在后续激活为普通物品；
- 宠物历史物品不补发 Agent 成长；
- 宠物历史物品不补发 OHM；
- Agent 自身未当场激活物品即使后续激活，也不补挖 OHM。

### 风险 4：“一人一 Agent”可能与部分用户的资产扩张预期冲突

#### 运营解释或建议

如果社区此前存在多 Agent、批量 Agent、Agent 组合策略或多槽位预期，需要主动校正，而不是等用户发现限制后再解释。

推荐叙事：

- 不是限制玩家，而是将 Agent 定义为账户级、长期连续的链上身份；
- 设计重点从“横向增加自动化账号”转向“纵向培养一个具备人格、装备、成长与 Stake 状态的 Agent”；
- 一人一 Agent 有助于降低多 Agent 刷量、资源垄断和规则复杂度。

### 风险 5：退出规则容易被简化为“惩罚”或“锁仓收益”

#### 运营解释或建议

退出机制涉及退出托管、罚金、留存者分配、资格门槛、自动注入与不可取消请求。公开表达中不宜只用“锁仓越久收益越高”概括。

应强调：

- 退出规则影响的是退出本金、等待期和资格；
- 退出队列中的 OHM 不再获得额度、素材挖掘权或退出罚金分配；
- 罚金不是协议收入；
- 罚金分配不是自由领取，而是按规则直接进入合格 Agent Stake；
- 用户应在确认前阅读完整退出提示。

## 七、建议的对外统一短版表述

### 产品一句话

> Lumiterra V2 是运行在 Monad 上的 Fully Onchain Agent 养成放置游戏：每位玩家培养一个长期成长的 Agent，让它执行游戏行为、管理链上资产，并通过真实产出兑现其 Stake 对应的 OHM 额度。

### Agent 一句话

> Agent 不只是自动化助手，也是玩家唯一的成长主体、策略容器与 OHM Stake 载体。

### Energy 一句话

> Energy 是由 MON 充值获得的不可交易游戏资源；它要么用于游戏成长，要么用于抽奖式 Bond，两条路径互不重叠。

### 宠物一句话

> 宠物让玩家免费进入并手动体验世界；拥有 Agent 后，玩家才会开启自动化、产出激活、成长记录与额度兑现循环。

### 经济机制一句话

> Bond 产生 OHM payout 与待分配利润，Stake 决定额度分配权重，而实际游戏产出决定额度兑现的速度。

### 风险边界一句话

> OHM 的解锁、注入、额度、兑现、自动复投与退出均受链上规则和实际游戏状态影响，不应被理解为固定或保证的回报。
