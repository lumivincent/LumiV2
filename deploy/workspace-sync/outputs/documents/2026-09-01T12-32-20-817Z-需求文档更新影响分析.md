# 需求文档更新影响分析

## 已确认产品事实

### 产品定位与经济结构发生重构

Lumiterra V2 的定位从“Agent 主导的 Fully Onchain 养成放置类游戏”扩展为“运行在 Monad 上、由 Agent 主导、以 OHM 为底层经济资产的 Fully Onchain 养成放置类游戏”。

经济框架不再围绕物品固定财富值、Token 奖池和装备回收展开，而是参考早期 OHM 的 Bond、协议利润与 Stake 机制：

- 抽奖式 Bond 是 OHM payout 和协议利润的唯一来源。
- 协议利润先形成未铸造的 OHM 待分配额度。
- 已解锁 OHM 可以注入 Agent，成为 Stake 本金及额度分配的唯一直接权重。
- Agent 通过实际游戏生产逐步兑现额度，挖出的 OHM 自动复投。
- 被动 rebase 被替换为“取得额度后仍需实际产出才能兑现”的机制。
- 固定物品财富值、财富转化率、Token 奖池、装备回收、Slow/Fast Redeem、合成财富守恒均已删除。

这意味着 OHM 的来源、分配权和兑现行为被明确拆分：Bond 产生利润额度，Stake 决定额度份额，游戏生产决定兑现速度。

### Energy 被拆分为两条互斥路径

MON 按 `1 MON = 1 Energy` 充值，Energy 不可交易，也不能直接兑换成 OHM 或 Stake 权重。

Energy 只有两种互斥用途：

1. 游戏行为、Agent 运行及成长消耗；
2. 抽奖式 Bond。

其中：

- 游戏成长 Energy 是游戏成本，不生成 OHM mint 额度。
- 只有抽奖消耗的 Energy 对应 MON 才进入 Bond 国库账本。
- 所有账户均可充值 Energy、参与抽奖式 Bond，不再以购买 Agent 为前提。
- 没有 Agent 时，宠物产出仍不能当场使用生产 Energy 激活；手动链上操作的 Gas 由玩家钱包支付。
- 购买 Agent 后才开放 Agent 运行 Energy 管理，自动操作使用不可透支的预付池。

因此，“玩游戏消耗 Energy 就为 Token 奖励提供价值”已经不是有效事实。游戏消费与 OHM 额度来源之间存在明确隔离。

### Agent 从自动化工具升级为经济载体

Agent 同时承担两项核心职能：

- 自动控制角色执行移动、战斗、采集、种田、合成和经济行为；
- 承载 OHM Stake、接收额度并自动复投挖出的 OHM。

每个人类账户最多购买、绑定和持有一个 Agent，不存在多 Agent 栏位、切换或多 Agent 并行经营。仓库也相应变为宠物与该账户唯一 Agent 共享。

只有已解锁 OHM 可以注入 Agent。注入、自动复投及退出请求均从下一个 30 分钟 epoch 边界生效；Stake 只决定额度分配权重，不直接决定素材生产效率。

### 宠物与 Agent 的关系更加明确

游戏仍只有一种角色模型，宠物和 Agent 是人类控制与自动控制两种入口，而不是两套成长系统。

- 玩家可以免费选择宠物形象进入游戏，但需要自行支付链上 Gas。
- 没有 Agent 时，宠物使用最低属性。
- 拥有 Agent 后，宠物属性参考该唯一 Agent，不再读取“账户最强 Agent”。
- 宠物的战斗属性取最低属性与 Agent 属性的 `33%` 中较高者；移动范围取 `5` 与 Agent 移动范围中较高者。
- 宠物背包容量固定为 2，不继承 Agent 背包。
- 同一账户最多由宠物和唯一 Agent同时参与同一遭遇。

初始装备继续与账户绑定，但“固定财富值为 0”“不可回收或投池”等描述已失去适用对象；当前有效限制是不能交易、借贷或作为升级材料。

### 成长价值从“财富转化”改为“生产效率”

Agent 成长阶段现在提升：

- 基础 HP；
- 移动范围；
- 行动速度；
- 背包容量。

Lv1–Lv9 对应基础 HP `1×–5×`、移动范围 `5–13` 格、行动速度 `1.0×–1.8×`、背包容量 `10–1,000`。

成长阶段和装备都不直接增加 Stake 权重或乘算 OHM 奖励：

- 成长通过移动、行动速度、容量及更稳定的高等级素材产出来提高兑现速度。
- 装备通过攻击、防御、暴击等职业属性提高行动效率、产出速度和可稳定获取的素材等级。
- 合成只消耗配方输入并生成物品，不增加成长进度，也不记录或继承固定财富值。

因此，Agent 等级和装备的经济价值应表述为“提升生产能力与额度兑现效率”，而不是“提高财富转化率”或“直接提高 OHM 奖励倍率”。

### OHM 额度需要合格素材兑现

只有归属 Agent 本人、且在原生产结算中当场支付 Energy 激活的合格基础素材，才能执行一次 OHM 兑现。

- 兑现比例只读取素材等级。
- Lv1 每件兑现 epoch 起始额度的 `1%`，Lv9 为 `9%`，中间等级按底数 `1.25` 的归一化指数曲线计算。
- 同一 epoch 的每件素材均以固定的 `AgentQuotaAtEpochStart` 为基数。
- 累计兑现不能超过 Agent 剩余额度。
- 每件素材最多结算一次，即使结算时额度为零，也不能留到以后再次尝试。
- 挖出的 OHM 不进入玩家即时可用余额，而是自动注回同一 Agent，从下一 epoch 增加 Stake。

宠物产出、购买 Agent 前取得的历史物品以及非当场激活的素材均不能补挖 OHM。Agent 自己取得的未激活物品，之后激活可按原资格补记成长进度，但不能补发 OHM。

### Bond、额度释放与退出形成新的完整闭环

抽奖式 Bond 每次对应一笔独立 Bond 购买，随机结果只在参与者之间重新分配 payout，数学期望必须与对应的确定性 Bond 一致。OHM payout 当场铸造并锁入 depository，只有解锁后才能卖出或注入 Agent。

Bond 利润进入全局待分配池，并按 8 小时半衰期逐步释放；每个 epoch 为 30 分钟。实际释放还受全局 Stake 是否存在、利润池余额及 reward-rate 上限约束，因此任何展示数值都不能解释为固定收益率。

退出机制改为 Shadow 式线性退出：

- 可以立即退出，或选择 `7–30 天`退出期。
- 立即退出及 7 天退出的罚金率均为 `50%`，之后线性下降，30 天为 `0%`。
- 请求确认后不可取消。
- 退出中的 OHM 停止获得额度、挖掘权和罚金分配。
- 罚金不是协议收入，也不增发或销毁 OHM，而是分配给满足连续生效至少 7 天条件的留存 Stake。
- 没有合格 Stake 时，罚金进入独立的 `ExitPenaltyCarryPool`，不能与未铸造的 Bond 利润池混用。

## 运营解释与建议

### 运营主叙事需要整体换轨

旧叙事的中心是“生产物品—积累固定财富值—合成或投入奖池—获得 Token”。这一闭环已经被删除，不能通过局部改词继续使用。

新的叙事主线应调整为：

> Bond 为协议经济创造待分配额度；OHM Stake 决定 Agent 的额度份额；Agent 的实际生产把额度逐步兑现；兑现结果自动复投，继续增强下一阶段的 Stake 权重。

这个结构的核心差异是“资本权重”和“游戏效率”相互配合但不混为一体：

- Stake 决定有多少额度可分；
- 等级、装备和实际行动决定额度兑现得多快；
- 单纯消耗游戏 Energy 不会创造 OHM；
- 单纯拥有 Stake 也不会自动完成全部兑现。

对外应优先解释这种职责分离，避免用户把系统理解为传统放置挖矿、被动质押收益或付费即增发。

### Agent 的叙事地位显著提高

Agent 不再只是便利性的自动操作层，而是游戏角色自动化、Stake 容器、额度兑现和自动复投的统一载体。“一人一 Agent”也使其更接近玩家的长期链上身份和经营主体。

运营可以强调：

- 免费宠物入口让玩家先体验世界；
- Agent 是后续获得自动运行与 OHM Stake 能力的升级；
- 每个账户围绕唯一 Agent 建立成长、装备、生产与经济策略；
- Agent 的价值来自长期配置、生产能力和资本承载，而不是批量购买多个 Agent。

但不宜把宠物描述为完整的免费收益入口：宠物产出不能获得 Agent 成长进度或挖 OHM，无 Agent 手动操作还需要钱包支付 Gas。

### 经济传播复杂度和合规风险明显上升

新增机制同时包含 Bond、随机 payout、OHM 解锁、Stake、epoch、额度兑现、自动复投及退出罚金。若直接使用“收益、复利、挖矿回报”等词汇，容易让用户误解为确定性金融回报。

建议公开内容按三层解释：

1. 先说明 Energy 的两条互斥用途；
2. 再说明 Bond、Stake 与游戏生产分别负责额度来源、分配和兑现；
3. 最后再解释 epoch、自动复投和退出。

所有示例都应标注为规则演示或模拟条件，不应将期望值、上限、典型生产效率或历史 OHM 模型类比包装成实际回报承诺。

### 既有内容需要全面复核

凡是出现以下概念的历史内容，都应进入待复核或停止复用状态：

- 固定财富值、财富守恒、财富转化效率；
- Token 奖池、投池权重；
- 装备回收、Slow Redeem、Fast Redeem；
- 多 Agent 持有、最强 Agent 属性继承、多 Agent 同场或共享仓库；
- 游戏 Energy 消耗产生 Token/OHM 额度；
- 历史未激活物品补发经济价值；
- Agent 等级或装备直接提高 Token/OHM 奖励；
- 挖出的 OHM 直接进入玩家余额；
- 固定、被动或保证的 Stake 收益。

仅介绍 Monad、Fully Onchain、统一角色模型、战斗/采集/种田和 Agent 自动执行的内容可以保留，但涉及经济结果时必须按照新文档重新核验。

## 主要风险

- **金融化误读风险：** “Bond、Stake、复投、退出罚金”组合容易被理解为投资产品。公开内容需要持续强调规则机制与不确定性，避免收益导向措辞。
- **随机机制误读风险：** 抽奖是 Bond payout 的随机分配形式，不应宣传为额外创造收益或“高倍稳赚机会”。
- **Energy 混淆风险：** 用户可能误以为全部充值 MON 都进入 Bond 国库，或所有 Energy 消耗都会支持 OHM。实际记账取决于 Energy 最终使用路径。
- **免费体验预期风险：** 免费创建宠物不等于零成本参与；链上 Gas 由玩家承担，且宠物产出不能直接挖 OHM。
- **自动复投流动性风险：** 素材挖出的 OHM不会即时到账，复投后还受退出机制约束。若只说“获得 OHM”而不说明去向，会造成可提现性误解。
- **数值承诺风险：** 30 分钟 epoch、释放半衰期、兑现曲线、退出罚金及成长时长虽已写入当前文档，但项目仍处于 Early Prototype。适合解释当前规则，不适合作为长期不变或结果确定的市场承诺。
- **体验门槛风险：** 一人一 Agent、购买后才能开启生产激活和 Agent 运行，会显著影响转化路径，需要避免继续使用“多 Agent 组合经营”等旧获客叙事。
- **系统理解风险：** Stake 决定额度、生产决定兑现速度、Energy 决定生产是否激活，三个层次容易被混成“投入越多、产币越多”的简单关系。

## 仍需团队确认的假设与问题

以下内容不能转化为公开承诺：

- Bond OHM 的具体线性解锁周期尚未定义。
- Agent 的购买价格、销售方式、供应量及是否可转让尚未说明。
- OHM 的初始供应、流通安排、市场上线及具体时间均未确认。
- Bond 抽奖的前端档位、单次投入范围及正式概率是否直接采用当前数值表，仍需产品与经济团队确认。
- 退出罚金、7–30 天退出期、30 分钟 epoch、8 小时半衰期等参数是否会在原型测试后调整，需要团队明确版本稳定性。
- 实际掉落率、Energy 成本、对象属性、装备数值、素材产量和实际 OHM 兑现速度仍依赖配置、模拟与测试。
- 宠物最低 HP，以及战斗、采集、种田的最低攻击、防御和暴击数值尚未确定。
- “Agent 是否支持多对一绑定同一个宠物”的 TODO 与“一人一 Agent、单一角色模型”的现行规则存在语义冲突，需要确认该 TODO 是否应删除，或其真实问题是否是 Agent 与宠物之间的控制关系。
- 文档提到“装备成长 Energy”，但当前合成规则又规定合成不额外消耗 Energy；需要确认“装备成长”具体指生产素材成本、未来强化系统，还是遗留措辞。
- `GameplayRevenueMON` 对应 MON 的最终用途、会计归属和是否构成协议收入，需要团队补充，当前只能确认其不进入 Bond mint 额度。
- Agent 购买前取得的宠物物品在购买后可付 Energy 激活，但不能补发成长或 OHM；相关界面是否会充分提示其有限用途，需要产品确认。
- Agent 退出后是否仍可继续执行纯游戏行为、如何管理剩余运行 Energy，以及退出是否影响 Agent 所有权，当前文档没有完整说明。
- OHM 解锁、出售、注入、退出托管及钱包到账之间的完整用户流程和风险提示仍需确认。

| “物品拥有固定财富值” | “素材用于成长、合成、交易或借贷；合格素材还可帮助 Agent 兑现已有 OHM 额度。” |
| “消耗 Energy 会产生 Token/OHM” | “游戏 Energy 用于支付生产和运行成本；只有抽奖式 Bond 产生 OHM payout 与协议利润额度。” |
| “把物品投入奖池获得 Token” | 删除。Token 奖池已不存在。 |

| “Agent 通过生产创造财富值” | “Agent 通过实际生产推进成长，并在具备额度时用合格素材逐步兑现 OHM。” |
| “质押 OHM 获得被动收益” | “注入 OHM 决定 Agent 的额度分配权重；额度仍需通过合格游戏产出兑现。” |

| “升级或装备直接增加 OHM 奖励” | “成长与装备提高生产效率和高等级素材获取能力，从而可能加快额度兑现，但不直接提高 Stake 权重或奖励倍率。” |

| “最高可获得某一回报率” | 避免用于市场传播。数值上限、期望值和典型效率只能作为当前规则说明或模拟结果。 |
| “等待 30 天即可无损退出” | “当前规则下，30 天线性退出的罚金率为零；市场价格、机会成本及规则调整风险不在该表述范围内。” |

当前最适合公开建立的核心表达是：Lumiterra V2 将 OHM 的经济分配与真实游戏生产连接起来，Agent 既是自动化角色，也是 Stake 载体；Stake 决定额度份额，游戏能力决定兑现效率。该表达仍应附带原型阶段、参数可能调整和不存在结果保证的边界说明。
