# Lumiterra V2 产品理解分析

- 分析日期：2026-08-26
- 产品阶段：Early Prototype
- 依据：`sources/requirements.md`、`sources/numeric-core.md`、`memory/current.md`
- 用途：内部运营理解与对外表达准备，不代表最终公开口径

## 一、核心结论

Lumiterra V2 已经形成一套较完整的产品骨架：它是运行在 Monad 上、由 Agent 主导的 Fully Onchain 养成放置类游戏；玩家可以先以宠物形象手动进入，也可以购买并配置 Agent，让 Agent 在同一套角色、玩法、成长和经济规则中自动行动。

对运营而言，当前最值得建立的产品认知不是“AI + Token”，而是以下三点：

1. **Agent 是控制和决策入口，不是第二套角色。** 人类宠物与 Agent 共用同一世界规则，区别主要在手动控制与自动执行、配置能力、运行预算和资产管理方式。
2. **战斗、采集、种田不是三个孤立系统。** 三者共享结算框架、共同推动 Agent 成长，并通过跨职业合成形成互相依赖的生产循环。
3. **经济系统有明确成本和价值守恒约束。** Energy、固定财富值、合成、交易、回收、奖池和借贷形成经济模块，但固定财富值不等于 Token 收益，初始模拟参数也不等于最终公开承诺。

当前适合继续做内部叙事和素材准备；在形成公开市场口径前，仍需补足 Agent 实际体验证明、Fully Onchain 的公开解释范围、Agent 售卖信息以及经济模块的上线边界。

## 二、已确认产品事实

以下内容直接来自当前需求文档或数值文档。

### 1. 产品定位与入口

- Lumiterra V2 运行在 Monad 上。
- 产品被定义为由 Agent 主导的 Fully Onchain 养成放置类游戏。
- 所有账户默认没有 Agent。
- 玩家首次进入可以选择宠物形象；宠物形象只影响外观，不改变属性或玩法能力。
- 创建宠物和领取初始装备不要求游戏内付费或 Energy 充值，但手动链上行为的 Gas 由玩家钱包承担。
- Agent 需要后续购买。

### 2. Agent、人类与角色关系

- 游戏只有一种角色模型；Agent 和人类宠物是两种控制入口，不是两套角色或成长系统。
- 宠物可以执行 Agent 能执行的游戏行为，并遵守相同的位置、能力、资源和链上规则。
- Agent 可以自动执行移动、战斗、采集、种田、合成和经济行为。
- 人类拥有 Agent 后，可以管理 Agent 的 Prompt、Context、Behavior Codes、启停、预算和资产。
- Agent 有五项 `0–100` 性格参数：风险偏好、目标专注、探索倾向、合作倾向、资源谨慎。这些参数影响决策权重和 Prompt，不直接改变链上数值。
- 没有 Agent 时，宠物使用最低属性；拥有 Agent 后，宠物部分属性可以继承账户最强 Agent 属性的 33%，并与最低属性取较高值。

### 3. 核心玩法与统一结算

- 核心生产行为包括战斗、采集和种田。
- 三种玩法共用 Health、攻击、防御、暴击、回合、成功、失败和超时框架，只替换职业属性与操作对象。
- 三种玩法都允许其他角色查看并动态加入正在进行的结算。
- 可拆分掉落按有效伤害占比分配；不可拆分稀有掉落只在有效伤害占比不低于 5% 的参与者中加权随机分配。
- 失败与超时不产生生产掉落、固定财富值或成长进度；已经发生的 Agent 运行、模型调用和链上执行成本不退还。
- 战斗连续 60 秒无操作时超时；采集和种田达到 50 回合时超时。

### 4. Agent 成长

- Agent 只有一条 Lv1–9 成长进度，不按战斗、采集、种田拆分职业等级。
- 三种玩法产生的合格有效成长掉落累加到同一条进度。
- 每阶段需要 2,000 件有效成长掉落；八次阶段提升合计需要 16,000 件。
- Lv1 到 Lv9 的目标有效生产时间为 720 小时；按照每天 12 小时有效生产的示例，对应 60 天。
- 720 小时是典型装备与正常路线下的平衡目标，不是协议保证的最短时间；提前取得高等级装备可能加快成长。
- 成长阶段只提升基础 HP、移动速度和背包容量，不限制装备穿戴，也不直接进入伤害或财富值公式。
- Lv1–Lv9 的基础 HP 倍率为 `1×–5×`，移动速度倍率为 `1×–2.5×`，背包容量为 `10–1,000`。

### 5. 装备与跨职业合成

- Agent 可以穿戴任意等级装备，成长阶段不是穿戴门槛。
- 装备可以自由混搭，不要求完整职业套装。
- 每个职业、每个等级有三种基础素材；三种素材各 1 件合成 1 份同职业、同等级精华。
- 一件职业装备需要另外两个职业的同等级精华各 1 份。
- Lv2 及以上装备还需要消耗同职业、同槽位的上一等级装备。
- 当前规则为固定配方、100% 成功率，合成本身不额外消耗 Energy。
- 合成遵循固定财富值守恒，不凭空创造财富。

### 6. 产出、Energy 与固定财富值

- 生产 Energy 只在实际掉落物完成激活时扣除。
- 空产出、失败和超时不扣除生产 Energy，也不产生固定财富值或成长进度。
- 没有 Agent 时，宠物产出进入容量为 2 的未激活背包，不获得固定财富值或 Agent 成长进度。
- 购买 Agent 后可以支付生产 Energy 激活购买前产生的物品并获得固定财富值，但这些历史物品不会补发成长进度。
- Agent 自动操作使用不可透支的预付运行 Energy 池；余额不足时会在收费点或安全行动边界暂停。
- `1 Energy = 1 MON`；Energy 由官方统一销售，不能在 Marketplace 交易。
- Energy 成本随物品有效生产等级增长，Lv1–Lv9 同级单件成本从 `1` 增长到 `16`。
- 同级固定财富转化率从 Lv1 的 `70%` 提升到 Lv9 的 `95%`。
- 固定财富值是系统价值计算单位，不等同于可保证获得的 Token 数量或市场收益。

### 7. 经济与资产流转

- 已激活物品可以参与合成、交易、借贷、回收或 Token 奖池。
- Agent 向 Token 奖池投入物品后不能撤回；固定财富值决定本期奖励权重，最终按权重分配 Token。
- 装备回收只读取装备固定财富值，不读取市场价格或历史投入。
- Slow Redeem 当前初始模拟值为 7 天等待和 5% 费用；Fast Redeem 当前初始模拟值为 10% 费用，且受每日动态额度限制。
- 单件装备可以作为一笔 P2P 贷款的抵押物；贷款期间可继续使用，但不能交易、转移、回收、投池或再次抵押。
- 主城仓库容量无限，归属于人类账户，同一账户下的宠物和全部 Agent 共享。
- 物品不能跨地点直接用于生产、合成或穿戴；多个模块需要验证位置或交互距离。

## 三、运营判断与建议

以下内容是基于产品事实形成的运营判断，不应直接视为产品承诺。

### 1. Agent 的核心价值应从“行动能力”解释

由于宠物和 Agent 可以执行相同类型的游戏行为，Agent 的差异不应被包装成“解锁另一套游戏”。更准确的价值方向是：

- Agent 能够持续自动执行世界行为；
- 玩家可以配置其目标、行为、性格、预算和资产管理方式；
- Agent 在同一套游戏与经济规则中做出决策，而不是停留在聊天或建议层面；
- 人类可以直接控制宠物，也可以管理 Agent，形成不同的参与方式。

运营上需要重点证明 Agent 如何决策、如何被配置、如何在真实世界状态中行动，而不是只展示 Agent 名称或 AI 对话框。

### 2. “免费进入”可以成立，但不能表达为“零成本游玩”

玩家无需先购买 Agent 即可通过宠物进入，并获得绑定初始装备；但手动链上操作需要玩家支付钱包 Gas，宠物生产物默认也处于未激活状态。因此更安全的内部表述是：

> 玩家可以在不购买 Agent 的情况下先进入世界并体验基础行为。

不建议直接使用“完全免费”“零成本”或“Free-to-Play”作为确定公开承诺，除非团队进一步确认 Gas、钱包、未激活产出和新手体验的最终方案。

### 3. 三职业的传播重点应是共同成长与经济互赖

战斗、采集和种田共享结算框架，成长进度合并，装备合成又要求跨职业精华。这意味着三种玩法更适合被解释为一个共同生产网络，而不是三个平行小游戏。

可继续验证的叙事方向：

> 不同行为推动同一个 Agent 成长，同时在装备与经济循环中彼此需要。

### 4. 经济传播必须先讲规则，再讲回报

文档定义了 Energy 成本、固定财富值、回收、借贷和奖池，但没有定义任何确定的市场收益。对外内容应优先解释：

- 行动存在真实成本；
- 物品具有协议定义的固定财富值；
- 合成遵循价值守恒；
- Agent 和玩家需要管理预算、库存、装备与风险。

不应把固定财富值、奖池权重或理论效率直接翻译为 APY、保本、稳定收益或“边玩边赚”。

### 5. Fully Onchain 需要用可见证据支撑

文档包含链上操作、协议随机数、原子结算、位置验证和资产流转规则，但公开传播仍需要明确回答：哪些状态、行为、Agent 决策结果和经济结算实际上部署并可验证在链上。现阶段可保留 Fully Onchain 定位，但大规模传播前应准备对应的产品演示和技术事实说明。

## 四、对外表达边界

### 当前相对安全的表达

- Lumiterra V2 运行在 Monad 上。
- V2 是由 Agent 主导的 Fully Onchain 养成放置类游戏。
- 玩家可以直接控制宠物，也可以购买和配置 Agent 进行自动行动。
- Agent 可以参与战斗、采集、种田、合成和经济行为。
- 战斗、采集、种田共同推动一条 Agent 成长进度。
- 三种职业通过跨职业合成形成互相依赖。
- Agent 可以配置 Prompt、Context、Behavior Codes 和性格参数。
- 产品仍处于 Early Prototype，机制和数值可能继续调整。

### 应谨慎表达

- `720 小时`、`60 天`：只能说明内部平衡目标，不能承诺玩家实际完成时间。
- `1 Energy = 1 MON`：虽属于当前规则，但涉及最终经济体验，应在购买、定价和产品界面确定后再作为市场重点。
- `70%–95% 财富转化率`：是协议数值关系，不是玩家收益率。
- `7 天 / 5% / 10%` 回收参数：文档明确为初始模拟值，不应作为最终规则发布。
- 33% 宠物属性继承：不能简化为 Agent 永久提升宠物 33%，实际规则还需要与最低属性取较高值。
- “自动运行”：不能延伸为无限运行、无成本运行或保证完成目标。
- Token 奖池：只能说明权重机制，不能承诺奖池规模、Token 数量、价格或收益。

### 当前不应承诺

- 上线、测试、售卖或 Token 相关日期；
- Agent 价格、数量、稀缺性、投资价值或二级市场表现；
- 固定收益、回本周期、APY 或 Token 保证；
- 所有经济模块会在同一版本同时开放；
- 任何特定数值、掉落率或成长速度不会继续调整；
- “零 Gas”“零成本”“完全被动收入”；
- 未经实际产品演示或技术确认的链上范围。

## 六、建议的内部产品表达

以下为运营工作版本，需要团队确认后再形成正式公开口径。

### 一句话内部理解

Lumiterra V2 是运行在 Monad 上、由 Agent 主导的 Fully Onchain 养成放置类游戏；玩家既可以直接控制宠物进入世界，也可以配置 Agent，让它在同一套玩法、成长和经济规则中持续行动。

### 三个产品表达支柱

1. **可配置的 Agent 行动**：Agent 不只是提供建议，而是能够在游戏世界中执行具体行为并管理预算与资产。
2. **统一成长的生产世界**：战斗、采集和种田共同推动成长，并通过跨职业合成形成互相依赖。
3. **有成本、有约束的链上经济**：行动、生产、资产和价值转换遵循明确规则，强调策略与管理，而不是保证收益。
