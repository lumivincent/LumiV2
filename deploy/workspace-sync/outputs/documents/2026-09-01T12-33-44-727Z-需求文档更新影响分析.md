# 需求文档更新影响分析

## 已确认产品事实

### 1. 经济模型从“物品财富值与奖池”切换为“Bond 利润—Stake 额度—游戏兑现”

本次更新完成了 V2 经济主轴的重构：

- Lumiterra V2 现明确为：运行在 Monad 上、由 Agent 主导、**以 OHM 为底层经济资产**的 Fully Onchain 养成放置游戏。
- 经济结构参考早期 OHM 的 Bond、协议利润与 Stake，但不采用被动 rebase：
  - 玩家先通过抽奖式 Bond 获得 OHM；
  - 已解锁 OHM 注入唯一 Agent，形成 Stake 本金和额度分配权重；
  - Bond 利润形成未铸造的待分配 OHM 额度；
  - Agent 必须实际完成游戏产出，并以合格基础素材兑现自身额度；
  - 挖出的 OHM 自动复投至同一 Agent，并在下一 30 分钟 epoch 增加 Stake 权重。

同时，以下旧经济接口已被明确删除，不能继续作为产品机制或内容表达：

- 固定物品财富值；
- 财富转化率；
- Token 奖池及其奖励权重；
- 装备回收；
- Slow Redeem、Fast Redeem；
- 合成财富守恒；
- 将生产、运行等游戏成长 Energy 计入 OHM mint 额度的逻辑。

### 2. Energy 被拆分为两条互斥路径

MON 可按 `1 MON = 1 Energy` 充值为不可交易 Energy，但 Energy 的用途被严格分流：

| Energy 用途 | 已确认结果 |
|---|---|
| 游戏行为、生产激活、Agent 运行、装备成长相关消耗 | 是游戏成长成本；不进入 Bond 国库账本；不产生 OHM mint 额度 |
| 抽奖式 Bond | 对应 MON 进入 Bond 国库账本；产生 Bond OHM payout 与协议利润 |

关键边界：

- Energy 不可交易。
- Energy 不能直接兑换 OHM。
- Energy 不能直接形成 Stake 权重。
- 只有已解锁且已注入 Agent 的 OHM 才形成 Stake 权重。
- **只有抽奖式 Bond 产生 OHM 与协议利润；游戏成长消耗本身不产生 OHM 增发额度。**

### 3. 抽奖被定义为随机化 Bond，而非独立博彩奖励池

每一次抽奖严格对应一笔 Bond：

- 玩家投入 `X` Energy，按照 Bond 定价获得随机数量 `Q` OHM。
- `Q` 当场铸造并锁入 depository，需解锁后才能出售或注入 Agent。
- 随机性只在不同玩家之间重新分配单笔结果。
- 单笔抽奖的 OHM 数学期望，必须等于同条件下确定性 Bond 的 payout。
- 价格读取 Token/MON 的 4 小时 TWAP、`1 MON` 固定地板与随时间衰减的需求计数器。
- 抽奖档位受到最大 payout 钳位时，仍必须进行期望配平，不能因钳位而暗中降低实际期望。

因此，公开叙事不应将其描述为“奖池抽奖”“额外发奖”或“随机空投”，而应准确描述为：**带有随机结果分布的 Bond 购买机制。**

### 4. Agent 成为唯一 Stake 载体，且每账户只能持有一个

账户与 Agent 的结构发生关键收紧：

- 所有账户默认没有 Agent，可免费选择宠物形象进入游戏。
- Agent 需要后续购买。
- 每个人类账户最多购买、绑定和持有一个 Agent。
- “一人一 Agent”是协议级限制。
- 不提供多 Agent 栏位。
- 不提供 Agent 切换功能。
- 同一账户在同一遭遇中，最多由宠物和唯一 Agent 同时参与。

这替代了旧版本中“每个账户可拥有多个 Agent、共享仓库、共同参与遭遇”的设计前提。

### 5. 宠物仍是免费控制入口，但不再是成长或 OHM 产出的替代路径

宠物与 Agent 仍属于同一种角色模型的两种控制入口，而非两套角色体系：

- 无 Agent 时，玩家可手动控制宠物参与游戏。
- 宠物默认使用最低属性，拥有 Agent 后可部分继承该唯一 Agent 的属性：
  - 战斗属性取宠物最低属性与 Agent 对应属性的 33% 中较高者；
  - 移动范围取 `5` 与 Agent 移动范围中较高者。
- 宠物背包固定为 2 格，且不继承 Agent 背包容量。
- 宠物可使用初始绑定 Lv1 剑、斧头、水壶完成新手生产。
- 初始装备不可交易、借贷或作为装备升级材料。

但宠物产出被明确限制：

- 无 Agent 时，宠物获得的物品默认未激活，不扣生产 Energy。
- 宠物产出不产生 Agent 成长进度。
- 宠物产出不产生 OHM 兑现资格。
- 宠物历史物品即使在购买 Agent 后补付生产 Energy 激活，也不补发成长进度或 OHM。
- 无 Agent 用户仍可充值 Energy、参与抽奖式 Bond；但宠物手动操作 Gas 仍由钱包自行支付，协议不补贴。

### 6. Agent 成长新增行动速度，成长与收益的关系被重新定义

Agent 的 Lv1–Lv9 成长阶段现提升四项基础能力：

- 基础 HP：`1×–5×`
- 移动范围：`5–13` 格
- 行动速度：`1.0×–1.8×`
- 背包容量：`10–1,000`

成长不直接带来以下结果：

- 不直接增加 Stake 权重；
- 不直接乘算 OHM 奖励；
- 不限制装备穿戴；
- 不额外消耗物品、Energy 或 OHM。

成长的价值来自效率提升：

- 更大的移动范围；
- 更高行动速度；
- 更稳定获取高等级素材；
- 更高背包容量带来的更少中断和更高持续产出能力。

装备的价值也被重新校正：

- 装备提升对应职业的攻击、防御、暴击等职业属性；
- 装备通过提高行动完成效率、素材产出速度和可稳定获取的素材等级，间接提升 OHM 额度兑现速度；
- 装备不直接乘算 OHM 奖励；
- 装备不再具有固定财富值、协议回收报价或固定赎回底价。

### 7. OHM 兑现是“有限额度的游戏内兑现”，不是素材直接产币

Agent 的 OHM 兑现机制已明确为额度制：

- Bond 利润进入全局待分配池。
- 每 30 分钟为一个 mining epoch。
- 全局池按 8 小时半衰期平滑释放，并受每 epoch 奖励率上限约束。
- Agent 按已生效 Stake 占全局已生效 Stake 的比例，获得新增 OHM 额度。
- 未挖完额度可跨 epoch 结转。
- 每个 epoch 开始时，Agent 锁定本 epoch 的额度基数。
- 合格基础素材按素材等级对应比例兑现该额度基数的一部分。
- 同一件素材最多执行一次 OHM 兑现。
- 实际兑现不得超过 Agent 当前剩余额度。
- 已兑现 OHM 自动注回同一 Agent，于下一 epoch 生效。

重要资格限制：

- 只有 Agent 自己获得的基础素材可能具备资格；
- 必须在原生产结算中当场完成 Energy 激活；
- 后续补付 Energy 激活的 Agent 历史未激活物品，可以按原资格结算成长进度，但**不能补挖 OHM**；
- 宠物获得的物品无论何时激活，都不增加任何 Agent 的成长进度或 OHM。

### 8. 退出从装备回收迁移为 Stake 的 Shadow 式线性退出

旧版装备回收被删除，OHM Stake 则新增明确退出框架：

- 可选择立即退出，或选择 `7–30 天`线性退出期。
- 立即退出与 7 天线性退出均对应 50% 退出罚金。
- 退出期越长，罚金线性下降；30 天为 0%。
- 退出请求确认后不可取消。
- 净 OHM 进入退出托管，到期后才进入钱包可用余额。
- 退出队列中的 OHM 不再获得 epoch 额度、素材挖掘权或退出罚金分配。
- 退出罚金不属于协议收入，也不产生新 OHM。
- 退出罚金分给符合资格的留存 Stake，并直接自动注入对应 Agent。
- 为防止临时注入抢罚金，只有在罚金结算快照前连续生效至少 7 天的 Stake 才有资格参与分配。
- 若当时没有合格 Stake，已铸造罚金 OHM 留在独立 `ExitPenaltyCarryPool`，不能混入未铸造的 Bond 利润池。

### 9. 合成与 P2P 借贷保留，但不再围绕协议定义价值运作

合成：

- 仍使用基础素材—精华—装备的固定配方。
- 合成销毁输入并生成目标物品。
- 合成不增加 Agent 成长进度。
- 合成不记录、继承或生成固定财富值。
- 合成不产生 OHM，不改变 Agent 未挖额度。
- V1 固定配方、100% 成功率，执行合成不额外消耗 Energy。

P2P 装备借贷：

- 单件装备同时只能担保一笔贷款。
- 成交后装备进入托管，借款人可继续使用，但不能交易、转移或再次抵押。
- 本金、最高 LTV、APR、期限由 Lender 设置。
- 协议只对实际支付或已收取利息收费。
- 不再依赖固定财富值、协议回收价或协议赎回价。

## 运营解释或建议

### 1. 运营叙事应从“边玩边积累物品价值”切换为“把游戏产出变成兑现效率”

旧叙事中的“固定财富值”“回收”“奖池”“物品投入获得 Token 权重”等表达，应整体退出主叙事。

更适合当前版本的核心叙事是：

> Lumiterra V2 不是让游戏行为被动产生 Token 回报，而是让玩家的 Agent 在链上经济中获得可兑现额度，再通过真实战斗、采集与种田，把额度逐步转化为自动复投的 OHM Stake。

建议对外始终同时说明三层关系，避免被理解为纯质押产品：

1. **Bond 负责产生 OHM payout 与协议利润；**
2. **Stake 决定 Agent 获得多少额度；**
3. **游戏产出决定 Agent 多快兑现额度。**

这能突出“Agent 主导的 Fully Onchain 游戏”与传统 OHM 机制之间的差异：不是持有后自动 rebase，而是**Stake 权重与游戏执行能力共同决定兑现过程**。

### 2. 应避免把素材、成长或装备表达成直接 OHM 奖励

“打材料赚 OHM”“升级提高 OHM 奖励倍数”“装备提高挖矿收益率”等短句存在误导风险。

更准确的替代表达：

- “素材用于兑现 Agent 已分配的 OHM 额度。”
- “高等级素材可更快兑现当期额度。”
- “成长与装备提升行动和生产效率，间接影响额度兑现速度。”
- “Stake 决定额度分配权重，游戏执行决定兑现效率。”
- “实际兑现受额度、素材资格、Energy 激活和生产结果共同约束。”

尤其不应将 Lv9 的素材比例、30 分钟 epoch、释放上限或典型兑现表包装为用户可获得的固定收益、固定 APR、保底回报或收益承诺。

### 3. “一人一 Agent”应成为产品定位与社区运营的重要锚点

这项变化不仅是账户限制，也改变了玩家的身份叙事：

- 玩家不是经营一个可无限扩张的 Agent 农场；
- 每个账户围绕一个长期绑定的 Agent 建立成长、装备、Stake、策略与行为人格；
- 宠物承担低门槛试玩和手动控制入口；
- Agent 是账户进入自动化运行、成长兑现和 OHM Stake 体系的唯一入口。

建议内容中使用“你的唯一 Agent”“一个账户，一条 Agent 成长与 Stake 路径”等说法，但避免在未确认 Agent 购买方式、价格、供应或转让规则前延伸为稀缺性、身份资产升值或购买紧迫性叙事。

### 4. 新手漏斗应从“先买 Agent 才能开始”调整为双入口

当前机制提供两类起点：

| 用户状态 | 可做行为 | 运营意义 |
|---|---|---|
| 无 Agent | 创建宠物、手动体验三类玩法、获得未激活物品、充值 Energy、参与抽奖式 Bond | 降低首次进入门槛，允许用户先体验或先理解 Bond |
| 有 Agent | 自动运行、管理运行 Energy、激活产出、推进成长、兑现 OHM 额度、自动复投 | 进入完整的长期养成与经济循环 |

建议新手内容明确区分：

- “免费宠物试玩”不等于“免费完整收益路径”；
- 宠物可体验核心玩法，但宠物产出不推进 Agent 成长，也不具备 OHM 兑现资格；
- 购买 Agent 后，也不能将宠物历史掉落补算为成长或 OHM。

这能提前降低“先囤宠物素材、后补买 Agent 获得追溯收益”的误解和客服压力。

### 5. 抽奖式 Bond 的传播应以透明规则与风险认知优先

“抽奖”是高传播词，但也最容易被误读为赌博、收益翻倍或高回报活动。建议采用以下叙事顺序：

1. 先定义它是 Bond；
2. 再说明结果存在随机分布；
3. 再说明单笔期望与确定性 Bond 对齐；
4. 最后说明 OHM 先锁定、解锁后才可出售或注入 Agent。

建议避免：

- “稳赚抽奖”
- “必得超额 OHM”
- “高倍回报”
- “抽中即赚”
- “稳赚不赔 Bond”
- “抽奖收益率”
- 将任一档位结果作为用户可期待的常规结果展示

如需做教育内容，可用“随机不改变机制设计的长期总发放目标，但单笔结果会不同”解释；避免把数学期望描述为个人结果保证。

### 6. 退出机制需要以“流动性选择与规则成本”表达，而非惩罚性营销

Shadow 式退出可以被理解为长期参与机制，但运营表达应保持中性：

- 可以解释为“即时流动性与等待期之间的明确规则选择”；
- 可以说明退出队列不再参与额度、素材兑现或罚金分配；
- 可以说明退出罚金由符合条件的留存 Stake 承接，而非协议收入；
- 不能暗示退出罚金会为任何留存用户带来确定增益；
- 不能用“别人退出就是你的收益”“锁得越久稳赚越多”等表达。

该机制涉及不可取消请求、罚金、托管和资格快照，产品教育、风险披露和操作确认页必须比普通游戏资产操作更清晰。

### 7. 现有内容资产需按风险优先级复核

| 既有内容类型 | 影响 | 建议动作 |
|---|---|---|
| 固定财富值、财富守恒、物品价值锚定内容 | 产品事实已失效 | 下线、归档或重写 |
| Token 奖池、投池权重、奖池分配内容 | 模块已删除 | 停止传播并明确废弃 |
| 装备回收、Slow/Fast Redeem、回收报价内容 | 模块已删除 | 下线；避免保留入口或 FAQ |
| 多 Agent、Agent 队列、Agent 切换、Agent 农场内容 | 与一人一 Agent 冲突 | 全面修改 |
| 无 Agent 不能充值 Energy 的内容 | 已失效 | 改为“所有账户可充值并参与抽奖式 Bond” |
| 宠物历史产出可补结算财富值的内容 | 已失效 | 改为“历史宠物产出不补成长、不补 OHM” |
| 装备提高财富转化效率或直接奖励的内容 | 已失效 | 改为效率、素材等级与兑现速度的间接关系 |
| “OHM / Bond / 自动复投”泛介绍内容 | 基础方向仍可用，但缺少机制边界 | 补充锁定、额度、游戏兑现与下一 epoch 生效规则 |
| Fully Onchain、Agent 自动行为、战斗采集种田内容 | 主体仍有效 | 更新为新的经济闭环版本 |

## 需要调整的公开表达

### 应停止使用的表达

- “物品自带固定财富值”
- “合成继承或守恒财富值”
- “投入物品进入 Token 奖池”
- “按投入财富值获得 Token 权重”
- “装备可以按协议报价回收”
- “Slow Redeem / Fast Redeem”
- “生产 Energy 会沉淀为 Token 或 OHM 价值”
- “游戏消耗 Energy 就能产生 OHM”
- “每个账户可拥有多个 Agent”
- “最强 Agent 为宠物提供属性继承”
- “宠物历史掉落后续可补结算经济奖励”
- “装备直接提高 OHM 倍率、挖矿倍率或财富转化率”
- “宠物可以作为 Agent 成长或 OHM 兑现的替代路径”

### 建议替换为的表达

| 原传播方向 | 建议公开表达 |
|---|---|
| 游戏产出价值 | “游戏产出用于推进 Agent 成长、装备循环与 OHM 额度兑现。” |
| OHM 机制 | “Bond 利润形成待分配额度，Agent 按 Stake 权重获得额度，并通过实际产出逐步兑现。” |
| 自动复投 | “合格素材兑现的 OHM 自动注回同一 Agent，并在后续 epoch 参与 Stake 权重。” |
| Agent 成长 | “成长提高移动、行动速度与容量，影响持续生产和高等级素材的稳定获取。” |
| 装备价值 | “装备提升对应职业的作战与生产效率，并间接影响额度兑现速度。” |
| 宠物入口 | “宠物提供免费手动体验入口；Agent 解锁自动运行、成长结算与 OHM 额度兑现。” |
| 一人一 Agent | “每个账户绑定唯一 Agent，成长、策略、Stake 与自动复投围绕同一 Agent 累积。” |
| 抽奖机制 | “每次抽奖对应一笔随机化 Bond；随机影响单笔结果分布，机制要求与确定性 Bond 的期望 payout 对齐。” |
| 退出机制 | “Stake 可按规则选择即时或线性退出；退出状态、等待期与适用成本以链上规则为准。” |

### 公开内容应补充的必要限制

涉及经济机制的内容，建议至少包含以下边界之一或链接至机制说明：

- OHM 兑现受 Agent 可用额度限制；
- 只有合格、当场完成 Energy 激活的 Agent 基础素材可参与一次 OHM 兑现；
- 已解锁 OHM 才能注入 Agent；
- 自动复投与其他 Stake 变化在后续 epoch 生效；
- 抽奖式 Bond 的随机结果不代表个人结果保证；
- 游戏成长 Energy 与 Bond Energy 是不同用途，不应混同；
- 退出涉及等待期、规则成本与不可取消请求；
- 数值、掉落、成本、价格与实际结果以链上规则和正式版本为准。

## 仍需团队确认的假设

### 1. Agent 购买、绑定与所有权规则

已确认每账户只能持有一个 Agent，但尚未确认：

- Agent 的购买方式、定价、支付资产与供应方式；
- Agent 是否可转让、出售、销毁或迁移；
- 转让后原账户是否可立即购买新的 Agent；
- Agent 与人类账户、宠物之间是否永久一一绑定；
- 需求文档 TODO 中“Agent 是否支持多对一绑定同一个宠物”的结论。

在此之前，不应公开使用“永久绑定”“不可转让”“限量 Agent”“身份 NFT”“稀缺 Agent”等说法。

### 2. 产品文档中仍存在的“多 Agent”遗留表述需要统一

当前需求文档已规定“每账户唯一 Agent”，但数值文档仍有少量继承旧结构的表述，例如：

- `WarehouseSharedBy = Pet + AllAgentsOwnedBy(HumanAccount)`；
- 有效成长掉落说明中出现“同账户其他 Agent”；
- 部分旧字段名称仍以多 Agent 结构表述。

这些内容与“一人一 Agent”的协议级约束不完全一致。建议产品、合约和前端统一为“宠物 + 唯一 Agent”，避免实现层或用户认知中保留多 Agent 入口。

### 3. “装备成长 Energy”与当前装备系统的具体对应关系

需求文档将“装备成长 Energy”列为游戏成长 Energy 的用途之一，但当前数值文档同时规定：

- 合成不额外消耗 Energy；
- 装备升级的配方 Energy 仅指获取基础素材时已经发生的生产 Energy；
- 尚未定义独立的装备强化或装备成长系统。

需确认“装备成长 Energy”是否：

1. 指基础素材生产激活成本，而非装备操作的额外成本；  
2. 预留给尚未写入需求的装备强化模块；  
3. 属于应从文档中删除或改写的旧措辞。  

确认前，运营不应宣传“升级装备需要额外 Energy”或“装备成长消耗 Energy”作为确定规则。

### 4. “抽奖式 Bond”的产品呈现、合规边界与地区策略

机制已确认随机化 Bond 的期望配平，但仍需确认：

- 对外正式命名是否继续使用“抽奖”“Lottery Bond”，或采用更中性的产品名称；
- 是否需要地区限制、年龄提示、风险提示或资格限制；
- 是否提供概率、公平性验证、历史结果和计算说明；
- 前端是否在用户操作前明确显示 OHM 锁定、解锁和可用状态；
- 是否需要将 Bond 操作与游戏内常规消费视觉上明显区隔。

确认前，应避免将其包装成纯娱乐抽卡或纯金融产品中的任一极端形式。

### 5. OHM Token 的正式名称、合约关系与用户可见资产路径

已确认文档使用 OHM 作为底层经济资产，但仍需确认：

- 该 OHM 是否为现有外部资产、协议内资产、映射资产或新部署 Token；
- 用户如何查看 Bond 获得的锁定 OHM、已解锁 OHM、已注入 Stake、未挖额度、自动复投和退出托管；
- Bond OHM 的具体线性解锁周期；
- Marketplace 结算 MON 与 OHM 之间是否存在用户容易混淆的资产路径；
- 是否允许、何时允许 OHM 在外部市场流通。

确认前，对外可使用“OHM”作为文档中的产品术语，但不应延伸为交易所、流动性、市场表现、资产价格或流通安排承诺。

### 6. 经济参数是否进入公开版，以及如何标注其状态

数值文档已写入多个具体参数，包括：

- `1 MON = 1 Energy`；
- Bond 使用 4 小时 TWAP、`1 MON` 地板；
- 30 分钟 epoch；
- 8 小时利润释放半衰期；
- 单 epoch 奖励率上限；
- 素材 Lv1–Lv9 的兑现比例；
- 7–30 天退出期与对应退出规则；
- 连续 Stake 满 7 天才具备退出罚金分配资格。

仍需确认这些参数在 Early Prototype 阶段是否已冻结、是否仅为测试参数、是否允许调整，以及对外应该展示到何种颗粒度。

在团队确认前，公开内容应避免将任何参数包装成长期固定制度，更不得据此计算或宣传 Token 回报、APR、收益率、回本周期、保底额度或经济结果。

### 7. 新手阶段的 Energy 与宠物体验设计

当前规则确认无 Agent 用户可充值并参与 Bond，但宠物产出不能在无 Agent 状态下使用生产 Energy 激活。仍需确认：

- 无 Agent 用户充值入口与 Bond 入口的具体产品引导；
- 是否应在宠物产出界面提前提示“购买 Agent 前无法激活生产产出”；
- 宠物背包仅 2 格导致频繁掉落销毁时的风险提示方案；
- 新手是否会被鼓励先体验玩法、先购买 Agent，还是先参与 Bond；
- 免费宠物体验的目标时长、任务与转化路径。

这直接影响新手教程、落地页、FAQ、社媒引导和客服话术。

### 8. 退出机制的交互、风险披露与运营支持方案

机制定义了退出期、罚金、托管与不可取消性，但尚需确认：

- 前端是否提供退出成本预览、到账时间预览和最终确认页；
- 部分退出、多个 Stake 批次和连续 Stake 年龄如何向普通用户解释；
- 退出罚金分配的资格状态是否用户可见；
- 退出托管资产的链上展示与客服查询方式；
- 是否需要针对误操作设置额外确认或冷静期。

在这些问题明确前，不建议用短图文简化为“随时退出”或“30 天免费提现”，因为其忽略了资格、排队、托管和已生效 Stake 等关键条件。
