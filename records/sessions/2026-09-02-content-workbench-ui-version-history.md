# 内容创作 UI 与版本历史优化

## 完成内容

- 将知识库资料选择从悬浮小面板改为居中弹窗：支持搜索、类型筛选、摘要列表、全文预览、暂存选择与确认后应用。
- 桌面端使用双栏“选择 / 预览”，窄屏自动切换为单栏，避免遮挡创作按钮和主表单。
- 压缩推文预览和请求输入区，把保存、定稿、发布操作移动到正文附近；快捷修改操作改为紧凑标签排列。
- 本次背景改为按需展开，创作会话历史默认折叠，继续修改输入保持可见。
- 为内容元数据增加正文版本链；保存正文变化时保留旧版，记录操作、时间、执行方式、模型和 API 用量，最多保留最近 30 版。
- 当前内容增加版本切换与恢复入口；从历史版本继续生成不会删除后续版本。
- 左侧内容记录显示版本数量。

## 重要判断

- 之前“找不到前面生成内容”的根因不是入口隐藏，而是草稿文件被原位覆盖，创作会话只保存了调整指令，没有保存每版正文。
- 版本应属于同一内容记录，避免在左侧制造大量重复草稿。
- 资料选择必须先帮助用户判断内容是否相关，再要求用户勾选。

## 验证

- ESLint 通过。
- Next.js 生产构建通过。
- 在本地网页验证桌面和窄屏资料选择布局、背景折叠、紧凑结果区与操作顺序。
- 页面控制台无错误或警告。

## 来源与边界

- 本次为工作台交互与本地数据结构优化，没有修改产品事实来源，也没有把知识库内容写入产品来源。
- 现有运行中的内容元数据和本地开发日志未作为本次代码改动处理。
