# 内容创作模型切换与近期记录复盘

## 本次完成

- OpenAI API 内容创作默认模型由 `gpt-5.6-terra` 切换为 `gpt-5.6-sol`。
- 同步更新服务端默认值、页面初始显示和环境变量示例。
- 通过本地 `/api/content` 配置接口确认当前实际模型为 `gpt-5.6-sol`。
- 检查最近一条推文从初稿到 V12 的生成记录、用户反馈和 API 用量。

## 主要判断

- 首轮需求明确要求三个方案，但当前系统提示强制只输出一个版本，用户意图在生成前被覆盖。
- 当前流程把“探索方向”和“精修选定方向”混为同一条线性版本链，导致模型持续润色上一版，难以真正换角度。
- 近期版本大量使用短句、抽象口号和 Crypto 惯用表达，但缺少一个具体而新鲜的中心判断，因此读起来像通用预热文案。
- 多轮要求里同时存在神秘、FOMO、缩短、事实准确、不要直述等目标，但系统没有记录用户保留了什么、拒绝了什么，后续轮次容易反复。
- 从旧版本继续修改时，正文可以回到旧版，但 API 隐藏会话仍可能续接最新 Response，版本正文与对话祖先不一致。

## 建议方案（待确认后实施）

1. 首轮进入“方向探索”，默认生成三个真正不同的创意方向，而不是三个近义改写。
2. 用户选中一个方向后进入“定向精修”，后续每轮只返回一个新版，并沿该方向保留版本历史。
3. 记录每轮的保留项、修改项和拒绝原因，替代仅保存操作指令的摘要。
4. 从历史版本继续时创建明确分支或重置 API 会话，避免旧正文接在新版本的隐藏上下文后。
5. 在最终定稿前增加轻量检查：核心观点、具体性、项目独特性、事实边界和是否存在通用 AI/Crypto 套话。
